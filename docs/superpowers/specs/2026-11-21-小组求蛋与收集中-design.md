# 小组求蛋与「收集中」设计

日期：2026-11-21

状态：产品口径已确认，待实施

目标分支：`test`

交互原型：`docs/prototypes/group-egg-request/2026-11-21/index.html`

## 1. 背景

当前“添加想收”和“母本计划收集”是两条割裂的流程：

- 母本页只能把未收集精灵加入本地计划；
- 小组页要重新搜索精灵、重新选择性格和条件，才能发布想收；
- 已有计划与组内想收无法在同一个任务视图里体现；
- 在发起交换时，其他组员的并行意向没有明确的产品处理方式。

本轮将“要收集什么”和“如何向小组发起交换”合并到同一张收集任务里，但保留小组需求广播和多人承接能力。

## 2. 已确认的产品口径

### 2.1 母本页签

母本页签调整为：

- `未收集`
- `收集中`
- `已收集`

三者为互斥状态，避免同一精灵同时出现在多个页签。

状态定义：

- `未收集`：本地没有合格母本，且没有未完成计划或换蛋任务；
- `收集中`：已有本地计划，或已经发布小组求蛋，或已有进行中的交换；
- `已收集`：本地已有合格母本，且没有仍需处理的小组任务。

如果母本已经收到，但小组需求或交换仍未结束，卡片继续留在 `收集中`，并明确显示当前剩余任务。

### 2.2 收集中页面

`收集中`使用母本页现有精灵卡样式：

- 四列网格；
- 不按蛋组聚合分区；
- 平铺展示当前计划单；
- 卡片聚合同一精灵的多个性格请求；
- 卡片显示用户下一步要做什么，而不只显示“想收”。
- 作为纯任务页，隐藏搜索、蛋组筛选、达标条件组合和推荐性格编辑等横条，只保留页签、当前小组和任务卡。
- 未发布的本地计划可从卡片右下角直接移出；已发布或进行中的任务必须通过需求操作处理，不能只删除本地计划伪装撤回。

建议卡片状态：

- `已计划`
- `可交换`
- `已发布`
- `等待回应`
- `收到新意向`
- `进行中`
- `待收蛋`
- `已完成`

### 2.3 计划与请求合并

计划单是主任务。一个计划单可以包含多条性格请求：

- 一个性格对应一条需求；
- 多条性格可以分别发布、被邀请、被接受和完成；
- 卡片显示整体进度，例如 `2/3 性格已安排`，不因单条请求成功而锁死整张计划单。

添加计划时分为两种情况：

1. 已有可作为交换对象的组员：
   - 可在一次动作中保存计划、发布组内需求并发送优先交换邀请；
   - 需求仍然对组内开放，不因指定优先对象而变成独占私聊。
2. 暂未形成可交换条件：
   - 只保存计划，不自动发布远程需求；
   - 用户可以稍后从 `收集中` 卡片主动发布求蛋。

「小组求蛋」检测到双向可交换成员时显示“可立即交换”。默认主按钮为“发布并邀请某人”，同时提供“只发布”。邀请只提高优先承接，不独占需求；机器人收到请求事件后发送中文群消息，并把目标成员明确绑定的 UID 作为 @ 依据。

### 2.4 并发意向

发起交换不应锁住整张计划单。

同一份需求可以同时存在：

- 我发出的交换邀请；
- 其他组员发来的交换意向；
- 多个潜在承接人。

接受交换时由服务端原子校验并占位。用户不需要在发起前预判亲本占用、绿窝、数量和时间是否一定满足。

状态处理：

- 对方接受后，对应的那一条性格请求进入 `进行中`；
- 数量大于 1 时，可逐份承接，直到数量满足；
- 对方撤回或拒绝时，该请求恢复为可继续承接；
- 其他意向不能在用户不知情时覆盖当前进行中的交换；
- 用户若想改选另一个人，需要先撤回当前邀请，再处理其他意向。

禁止使用以下模糊提示：

- `已被其他交换占用`
- `需求已满`

必须写清具体事实和人物，例如：

- `小布已接受这条踏实蛋，当前已由小布承接`
- `这份固执蛋已有承接人，还剩 0 份`
- `你还没有接受新的意向，小布仍在等你回应`

### 2.5 小组页入口

小组页原来的 `＋ 添加想收` 改为 `去计划添加`。

点击后直达：

`收集 · 母本 · 收集中`

不再在小组页打开独立的“添加想收”选精灵页面。

### 2.6 小组求蛋弹层

点击 `收集中` 卡片打开简单版“小组求蛋”弹层。

标题：`小组求蛋`

保留：

- 精灵头像、名称、形态；
- 目标性质；
- 目标体型 / 声音奖牌；
- `谁能补我`卡片；
- 性格选择；
- 体型选择；
- 声音选择；
- 绿窝勾选；
- 发布小组选择；
- 取消 / 发布按钮。

删除：

- `我的需求 · N` 区域；
- 性别选择行。

自动填入：

- 性格按当前母本缺口预填；有几个缺口就默认选中几个；
- 声音必须使用当前页面已选中的目标声音，不能写死为 `+100`；
- 体型使用当前目标体型。

头部排版：

- 头像、名称、形态、目标奖牌作为主体；
- 性格竖向排列；
- 性格列位于 `谁能补我` 卡片左侧。

### 2.7 100% / 0% 体重

体型在普通目标之外增加可选的极端蛋重要求：

- 目标体型为大块头时，显示 `满体重 100%`；
- 目标体型为小不点显示 `零体重 0%`；
- 单选，可不选；
- 默认不选；
- 不选表示仍按原来的大块头 / 小不点求蛋；
- 选后再次点击可取消；
- 不能同时选择普通档与极端档。

### 2.8 绿窝

`小组求蛋`弹层提供绿窝勾选项。

绿窝和普通需求复用现有的发布字段与显示口径。没有选择性格时不能发布绿窝需求。

## 3. 状态与数据关系

产品层统一使用“收集计划单”作为主对象，内部包含：

- 精灵 / 蛋；
- 每个性格对应的一条请求；
- 目标体型；
- 目标声音；
- 极端体重选项；
- 绿窝要求；
- 目标小组；
- 需求状态；
- 交换意向与邀请状态；
- 完成进度。

服务端继续以现有需求与交换记录作为实际状态来源。前端负责把同一精灵、同一目标下的多条需求与交换聚合为一张可理解的任务卡。

## 4. 机器人提醒

允许将换蛋请求接入机器人提醒，至少覆盖：

- 收到新的交换意向；
- 对方接受请求；
- 对方撤回或取消；
- 当前请求已有其他组员承接，并写明承接人；
- 计划单进入待收蛋状态。

发起过程中收到新意向后，不打断当前表单；使用轻提示或角标，提交后再进入任务列表处理。

### 4.1 真实队列事件（2026-11-21）

换蛋动作进入云端通知队列，复用已绑定的 QQ 群机器人：

- `kind: exchange`
- `event: request | accepted | cancelled | completed`
- `message`: 已整理好的中文群消息，可直接发送
- `uids`: 目标成员当前明确绑定的游戏 UID；机器人可据此 @ 对方
- `groupId` / `groupName` / `tradeId`: 仅用于插件调试与去重，不展示给群成员

事件在换蛋状态事务中写入；群未绑定时不写通知，也不影响换蛋主流程。机器人领取后仍重新核对当前交易状态，已失效的请求不会继续发送。发送失败退避重试；目标未绑定 UID 时仍可发群消息，只是不 @ 人。

## 5. 明确不在本轮范围

- 不在发起阶段预判绿窝、亲本占用、数量和时间是否一定满足；只在接受时由服务端校验。
- 不支持“先行选择某个组员后，整张计划单被独占锁定”。
- 不恢复独立的小组页“添加想收”精灵搜索页。
- 本轮不打包、不部署、不发布正式站。

## 6. 验收标准

- 母本页显示 `未收集 / 收集中 / 已收集` 三个互斥页签。
- 从 `未收集` 加入计划后，精灵进入 `收集中`，不在 `未收集` 重复显示。
- 小组页 `去计划添加` 能直达 `收集 · 母本 · 收集中`。
- `收集中` 使用母本四列卡片，不按蛋组分区。
- 点击 `收集中` 卡片能打开 `小组求蛋`。
- 性格按缺口自动带入，声音按当前目标自动带入。
- 大块头显示 100% 可选项，小不点显示 0% 可选项，默认均不选。
- 删除“我的需求”和性别行。
- 性格竖排在“谁能补我”左侧。
- 多人意向可以并存；接受一条时不影响其他未满请求。
- 所有并发冲突提示必须写明具体承接人和剩余数量，不出现模糊提示。
- 换蛋请求、接受、取消和确认收到会生成真实机器人队列事件，并包含可直接发送的中文消息。
- 存在双向匹配时，主操作可一步完成“发布需求 + 邀请最优组员”；没有双向匹配时只发布到小组。
- 375 / 390 宽度无横向溢出，弹层底部操作可见。

## 7. 原型

当前交互原型：

- `docs/prototypes/group-egg-request/2026-11-21/index.html`

原型已覆盖：

- 母本 / 种公两种入口；
- 大块头 / 小不点；
- 100% / 0% 可选状态；
- 绿窝；
- 小组选择；
- 性格自动预填；
- 375 / 390 浏览器验证。

原型尚需按本规格修正：

- 声音从当前目标动态带入；
- 母本信息头部重排；
- 性格竖排在 `谁能补我` 左侧；
- 增加 `收集中` 任务卡态；
- `去计划添加` 与计划页联动。
