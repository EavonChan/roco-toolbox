**这四天做的是「小组内的换蛋闭环」，做得比上一轮更完整（接单上窝是真创新）；但产品对外仍然是关着门的：85 台设备里只有 11 个人真正走到了换蛋环节，日活从 29 掉到 5。**

## 3. 视角一：资深模拟经营 / 卡牌收集策划

**评分：70 → 72（+2）**

### 3.1 做对的：把「需求」变成了「可执行的生产计划」

策划视角最值钱的一点：**需求单不是愿望，而是生产任务**。
「接单上窝」把一条需求（蛋 × 性格 × 性别 × 体型 × 声音）翻译成「哪个号、哪只母本、哪只种公、进普通窝还是学院小窝、大概几成概率出」，还处理了「窝不够时 1:2 共用亲本」。这是模拟经营里标准的**产能分配**问题，市面上没有同类工具做。

这比「做一个集市」更策划：集市解决「找得到人」，上窝解决「接得住单」。

### 3.2 问题的根：产品被收窄成「熟人小组的私有工具」

- 删掉「个人求蛋 / 换什么」后，**不登录、不入组的人已经没有任何换蛋功能**。
- 需求只能在组内被看见；组与组之间不互通。
- 36 条 open 需求（68%）没人接，说明**组内供给池不够**，而产品没有任何「没人接怎么办」的动作（提醒、推荐、跨组、公开求蛋板）。

策划上这是「需求池 > 供给池」的经典失衡。解决办法不是加页面，而是**降低供给方的参与成本**（见 §6）。

### 3.3 验收环节缺失，「货不对板」只是从群里搬到了组里

现在结单只有需求方（或组长）点一下「确认完成」，没有：
- 承接方的「我已交付」；
- 交付时的核对清单（蛋物种 / 性别 / 性格 / 体型牌 / 声音 / 父母本）；
- 不符时的原因记录。

也就是说：**用户最担心的「货不对板」，产品并没有真正解决**，只是把交易从公开群挪到了熟人组，靠人情兜底。

### 3.4 口径治理有隐患

`docs/产品交互规范.md` 明确「小组口径自 2026-10-29 起只读展示，不再提供修改入口」。历史组的旧目标一旦与组员个人目标不一致，组长**无法修正**，只能解散重建。对一个要长期运营的收集玩法，这是会积累怨气的设计。

### 3.5 策划侧建议（按优先级）

1. **给「没人接的单」一个出口**：发布超过 N 小时无人接 → 允许一键生成「求蛋卡」发到组外（见 §6.1）。
2. **补验收**：接单即生成「验蛋卡」，交付时双方各点一次；不符可选原因。只记事实，不做积分。
3. **恢复组口径编辑**（至少组长可改，并提示会影响缺口计算）。

## 4. 视角二：收集型玩家

**评分：66 → 65（−1）**

> 说明：老用户体验是**上升**的（上窝名单、缓存秒开、认领即时反馈、防误触）；但产品整体对新人是**更冷**的，且删除了一条不需要登录的换蛋入口。综合净 −1。

### 4.1 老用户得到的（真实提升）

- 切组不再空屏，先出缓存再刷新；轮询从 15 秒放宽到 60 秒且先比版本号，**不再每 15 秒卡一下**。
- 认领点下去立刻变「我认领了」，不用等列表刷新。
- 卡片外只显示状态，**滑动不会误接单**；操作集中到详情里。
- 家园「接单上窝」直接告诉你「这个号上哪两只、进哪个窝、几成概率」，这是玩家真正会照着做的东西。
- 结单后有「XX 已确认完成你的 N 单」「组内排行第 N 名」的回执，有正反馈。

### 4.2 新用户面对的四面墙

```
打开 App（85 台）
  ├─ 要装采集器 / 抓包才能导入 → 16 台（19%）
  ├─ 要登录（云同步身份）→ 19 台（22%）
  └─ 要加入小组并被认出来 → 11 人（13%）
        └─ 才能第一次看到「换蛋」长什么样
```

- 没有示例数据 / 演示看板，**不抓包就永远是空页面**。
- 小组页未登录时只有一句「先登录」+ 一个邀请码输入框；没入组时只有「新建 / 加入」。
- 「我缺的 / 需求中心 / 共同寻找」三个子页语义相近，新人要试错才知道去哪。
- 术语密度高：蛋、蛋组、档位、体型、声音、种公、母本、产线、上窝、承接……**第一屏没有一个词是新人自带的**。
- 错误提示偏工程化（「带上接口路径与返回内容」），普通玩家看不懂。

### 4.3 提醒能力仍然弱

只有停在小组页时 60 秒轮询才生效；离开 App 没有任何通知。别人接了你的单、孵出来了，你要**自己想起来回来点一下**才知道。

### 4.4 玩家侧建议

1. **首启示例看板**（假数据，标注「示例」），让人 10 秒看懂这工具能干嘛，再决定要不要抓包。
2. **术语表 / 首次提示**：在「我缺的」上方用一句话解释「缺什么、谁能补、怎么换」。
3. **导入后给出口**：「看我还缺什么」→ 直达需求中心并预选刚导入的蛋（上一轮就提过，仍未做）。
4. **组外可看**：分享链接打开是只读页面，不登录也能看「这个组在找什么」，再决定入组。

## 6. 视角四（新增）：创新点与可玩性

### 6.1 先把「换蛋」拆成 6 个环节，看三种方案各强在哪

| 环节 | 群清单（主流） | 蛋神集市 | 本项目现状 |
| --- | --- | --- | --- |
| ① 整理我能给的蛋 | 手工整理，极易过期 | 采集器自动 | **自动采集 + 自动发布** ✅ |
| ② 发布 | 超长文本刷群 | 上架到集市 | 组内需求卡 ✅/⚠️ |
| ③ 被谁看见 | 靠群活跃度、运气 | 集市流量 | **只有组内 11 人** ❌ |
| ④ 需求确认 | 私聊问「你有没有」 | 下单 | 接单 ✅ |
| ⑤ 核对口径 | 人肉对父母本，容易错 | 平台字段 | **五字段结构化（蛋/性格/性别/体型/声音）** ✅ |
| ⑥ 交付与验收 | 无凭证，货不对板只能认 | 平台托管 + 信用 | 需求方单方点完成 ⚠️ |

**结论：本项目在 ①⑤ 已经是全场最强，在 ③⑥ 最弱。**
而 ③（被别人看见）和 ⑥（敢不敢交付）恰好就是「怎么吸引别人用」的两个命门。

### 6.2 已有的、别人抄不走的资产

「接单上窝」把需求直接算成上窝名单 + 概率（学院 100% / 同性格 60% / 单方 30%），还处理窝不够时的 1:2 共用。
这件事蛋神不做（它只负责撮合与履约），群清单更做不了。**这是产品的技术护城河，应该围绕它做传播，而不是再做一个集市。**

### 6.3 三个可落地的创新点（按性价比排序）

#### 创新点 1：「求蛋卡 / 换蛋清单」可分享链接（最高优先）

不是回到「复制一坨文本」，而是**把清单变成可计算的网页**：

- 我在组里点「生成换蛋卡」→ 得到一个链接/二维码（无需登录即可打开）。
- 页面只读展示两栏：**我能给的**（蛋 × 档位 × 性格 × 性别，自动从已发布资源算）+ **我在找的**（当前 open 需求）。
- 对方打开后，可以「用我的数据比一下」：上传自己的备份或抓包，**立刻看到「我能补你 3 条」**；不想上传也能只读浏览。
- 页尾放邀请码 / 「加入这个小组」。

为什么这是最划算的：**群里本来就要发清单**，产品现在把这条路删了（`CopySheet` 已成孤儿组件）。恢复它不是倒退，而是把「长文本」升级成「对方能直接算的链接」，顺手完成获客。
技术上不需要新表：先用 URL 内嵌摘要（base64 + 长度上限），后续再加 D1 短链与访问计数。

#### 创新点 2：「验蛋卡 + 双向确认」解决货不对板

- 接单成功即生成一张验收卡：蛋物种、性别、性格、体型奖牌、声音 dB、父母本、概率。
- 交付时：承接人点「已交付」；需求方点「确认无误」。
- 不符时选原因（性别错 / 性格错 / 体型错 / 声音错 / 没孵出来），只做**事实记录**，不做扣分经济。
- 组内成员页显示「已交付 / 被确认」两个数（现在只有「已结单」一个数）。

这不会变成蛋神：不做托管、不做积分、不做机器人，只把「口头承诺」变成「可回看的记录」。

#### 创新点 3：把「接单」做成有反馈的组内任务（可玩性）

现在已经有素材，只是没被产品化：

| 已有 | 升级成 |
| --- | --- |
| 结单 toast 里的「组内排行第 N」 | 成员页常驻**周榜**（本周结单 / 被确认 / 连续周） |
| 「XX 成功孵出 性格性别·精灵名」 | 里程碑：第 1 / 5 / 10 / 25 单，首次双蛋组，首次异色 |
| 覆盖矩阵 | 母本链「首次点亮」时刻（一次性动效即可） |
| 游戏活动蛋 | 组内「本期目标」：一起把某个蛋的某个档位补齐 |

**不要做的**：积分兑换、抽奖、代币、机器人代打、账号托管。这些是蛋神的护城河，也是合规雷区。

### 6.4 增长路径（具体到动作）

1. **单组跑通 → 复制**：先把现有 7 个组里最活跃的 1 个跑到「周完成 ≥ 5 单」，把过程写成组内公告。
2. **每人一张卡**：让这 5–10 个人 Weekly 各生成一张换蛋卡发到自己的群；卡片是唯一对外物料。
3. **衡量口径换成**：`分享卡打开数 → 点「我能补」数 → 入组数 → 首单完成数`，而不是安装量。
4. **北极星指标**：**每周完成的换蛋单数**（其次：有人接单的需求占比）。它同时反映供给、需求和履约。
