# 小组求蛋与「收集中」实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把母本计划、小组想收和小组求蛋合并到一条可追踪的任务流，并修正求蛋弹层的自动填充与并发状态文案。

**Architecture:** 本地 `motherPlan` 继续作为计划意图；`egg-matching` 的需求与交换继续作为小组事实来源。新增纯函数把两边聚合成 `收集中` 卡片，新增单精灵 `小组求蛋` 表单，不在发起阶段锁资源；接受、取消和数量冲突继续由服务端原子校验。

**Tech Stack:** React 18、TypeScript、Vitest、Testing Library、现有 `ModalSurface` / `PetCardLayout` / `useEggMatching`。

**Spec:** `docs/superpowers/specs/2026-11-21-小组求蛋与收集中-design.md`

## Implementation Status

2026-11-21：

- 已完成：三页签导航、母本计划聚合、`收集中` 四列卡、小组页 `去计划添加`、单精灵 `小组求蛋`、声音自动填入、性格竖排、100% / 0%、绿窝、具体并发状态文案。
- 已完成：机器人换蛋事件队列。发起、接受、取消、确认收到会生成 `kind: exchange` 事件与可直接发送的 `message`，支持失败退避重试和领取前状态复核。
- 已完成：双向匹配时的小组求蛋快捷主操作“发布并邀请最优组员”，并保留“只发布”；邀请不独占需求，其他组员仍可回应。

## Global Constraints

- 只在 `test` 分支实施；不打包、不部署、不改正式站。
- `未收集 / 收集中 / 已收集` 为互斥页签。
- 计划单是主对象；一条性格是独立子请求。
- 发起请求不锁整张计划单；不预判亲本占用、绿窝、数量和时间。
- 禁止出现“已被其他交换占用”“需求已满”等模糊文案，必须写明承接人、性格和剩余数量。
- `收集中` 不按蛋组分区，使用母本四列卡片。
- 声音必须从当前目标自动带入；100% / 0% 默认不选。
- 任何生产代码改动必须先有失败测试。

## Review Focus

- 同一条性格在提议、接受和完成之间切换时，卡片要显示具体人物与剩余数量，不能丢失任务。
- 计划项与已发布需求聚合到同一张卡时，不能重复出现或把不同性格合并成一条不可操作的需求。
- 没有登录或没有小组时，本地计划仍要可见，但不能伪造已发布状态。
- 目标体型/声音改变后，未发布的计划使用当前目标，已发布需求保持服务端快照。
- 多性格中一部分已安排、一部分仍开放时，卡片不能整卡锁死。
