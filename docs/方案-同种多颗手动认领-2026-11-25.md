### 可行性（改动量 / 风险 / 回退）

- **改动量**：3 个文件、约 150~200 行（含测试）；不新增依赖、不新增后端接口，认领/拆开走现有 `mutate` 通道。
- **最难的一处不是 UI**：服务端 `stock-sync` 删的是「客户端这次没送上来的行」。所以保底真正要做在客户端 reconcile（别再删），行随库存一起送上去、服务端自然保留——这一半已落地并用真实抓包验证过；**代价是老客户端（不会发这一行）仍会被服务端删掉**，得等它更新，不需要动服务端。
- **风险**：① 认领前同一颗蛋显示两张卡（多出来那张是虚线「待认领」），不认领就一直留着 → 给了「暂不认领」和「✕ 这颗不在了」两个出口；② 用户记不住蛋重就分不清——这是数据本身的限制，页面只能把时间/蛋重/蛋高/性格都摆出来，不替他猜；③ 认错 → 靠「拆开认领」兜，拆开时背包那张的体型/声音先置空（合并后的这两个值可能来自家蛋推算），下次背包抓包自动补回。
- **回退成本**：低。字段全部可选，UI 是面板内新增一屏；不做就把入口去掉，数据层不受影响。

## 一、为什么必须手动（一句话证据）

两份抓包对比（E2）：家蛋 id 是 `["uid","home",actorId]`、背包蛋 id 是 `["uid","bag",instanceId]`，**没有任何公共字段可以硬链接**；两侧唯一共有的是**物种**。性格只有背包侧是真实值、家蛋是推算值；蛋重/蛋高**家蛋根本没有**；时间只有背包侧有。

所以同种 ≥2 颗时，任何「按顺序 / 按性格 / 按时间窗」的自动配对都只是猜。E2 已实测：合成同种两颗后，现有 `candidates.length !== 1` 分支会**跳过合并**；而家园快照完整且已空时，家蛋行被当「消失」删掉，结果只剩一颗「未知来源」的背包蛋，**父母 / 自产 / 性格全丢**。

> 现状保留：**异种 / 唯一候选**的自动合并继续留着（E2 已证成立，不在这次改动里），只有候选 ≥2 才进待认领。

### 入口位置（我的选择，需要你确认）

- **放蛋仓顶部、搜索框上面**，第一条内容，琥珀色（规范里「提醒 / 待确认 = amber」）。有 N 颗才出现，0 颗不占高度。
- 备选（不推荐）：塞进筛选栏做成「待认领 2」小按钮——省高度，但用户扫不到，违背「要能一眼看到」。
- 待认领的卡**继续留在网格里**（不藏起来）：父母/自产只在这张卡上看得到，藏了等于把它们锁进认领页。代价是同一颗蛋在认领前会显示两张卡，横幅第二行直接说明「认领后两张卡会合成一张」。

### 认领页的操作

1. 左列点一张（卡变绿框 + 右上「已选」）→ 右列点一张。
2. 底部实时写当前选择；**物种不同 → 按钮不可点 + 红字原因**（唯一的自动判断，只做「不可能是同一颗」的否决，不做建议）。
3. 「合并这两颗」→ 落库 → 该组从两列里消失、横幅计数减一；最后一组做完显示「都认领完了」。
4. 「暂不认领」→ 直接回蛋仓，两边的卡都留着，下次导入还能接着对。
5. 左卡右上角「✕」= 这颗不在了（已孵化/已放生）：作废这一行、不再提醒。**没有这个出口，横幅会永远消不掉。**

## 三、数据与规则（保底）

### 3.1 新增三个字段（`StockEgg` / `WorkflowEgg`）

```ts
/** 家蛋行已从「家园完整快照」里消失、但还没认出对应背包蛋：保底保留、等用户认领。 */
claimPending?: boolean;
/** 这个背包蛋是某次快照里新出现的、还没认领；值是首次进背包的抓包时间（ms）。 */
claimArrivedAt?: number;
/** 认领/自动合并前的家蛋侧标签（只有这三项会被背包值覆盖），拆开时原样还原。 */
claimBackup?: { nature: string; body: EggRecord['body']; voice: EggRecord['voice'] };
```

### 3.2 `reconcileEggStock` 规则

| # | 场景 | 现在 | 改后 |
|---|---|---|---|
| R1 | 家园**完整**快照里没有这颗家蛋，且没有 `capturedEggId` 链接 | **删掉**（父母/自产/性格一起没） | **保留**，`claimPending = true`；`location` 仍 `'home'`；不动 `lastConfirmedAt`；`listed = false`；**不写 `missingFromCapture`** ✅ 已实现 |
| R2 | 家蛋又出现在家园完整快照里 | — | 清 `claimPending`，走原逻辑（`lastConfirmedAt` 刷新）✅ 已实现 |
| R3 | 背包里出现新实例（本次没被合并） | 直接插行 | 插行并写 `claimArrivedAt = bag.capturedAt`；**已存在的行不覆盖** ⏳ 待 UI 轮 |
| R4 | 背包行从**完整**背包快照里消失 | 删 | 照旧删（蛋真的没了，含 `claimArrivedAt` 行） |
| R5 | 合并成功（唯一候选 / `capturedEggId` 链接） | 写 `capturedEggId` | 另外：清 `claimPending` ✅ 已实现（`claimArrivedAt` / `claimBackup` 待 UI 轮） |
| R6 | **待认领行不参与自动合并** | 会参与 | 候选限定 `location === 'home' && !claimPending`（否则用户刚拆开，下次导入又被自动合上）⏳ **待你定**：这轮没改，因为会动 E2 已认可的「唯一候选自动合并」口径 |
| R7 | 旧数据（没有这三个字段） | — | 行为与现在**完全一致**；上线后第一次「家园完整快照里消失」才产生待认领 ✅ |
| R8 | 认领后的行再同步 | `capturedEggId` 链接幂等 | 不变（已有测试守着） |

> R1 落地的实测：拿 E2 的两份真实抓包、把两颗家蛋合成同种（极端场景）跑一遍——
> 修前 `120 行 / 0 行家蛋 / 父母全丢`，修后 `122 行 = 120 背包 + 2 待认领家蛋`，
> 并且待认领行 `provenance=self-bred`、母亲/父亲（布是石×火豆丁、柴渣虫×柴渣虫）都在。

### 3.3 服务端 `stock-sync` 必须同步改（**关键，不改等于白做**）

现在 `applyEggAction` 的 `stock-sync` 分支：完整快照里没出现 → `missingFromCapture = true`，然后被 filter 删掉（`eggWorkflow.ts` 里那段 `state.eggs.filter(...)`）。客户端即使保底保留，服务端也会删——下次水合又没了。

改成：

- **家蛋行**（`location === 'home'`）在「家园完整快照」里消失 → **保留**，`claimPending = true`；
- **绝不给待认领行写 `missingFromCapture`**：这个标记会被三处当「失效蛋」清掉（`autoListStock` 跳过、`allocate` / `cancel` 里的 filter、`functions/_lib/collectionGroupsStore.ts` 的清理 SQL），一旦写上，父母又会被删，还是同一个坑；
- 背包行照旧（真的没了就删）；
- `normalizeEgg` 接受这三个字段，`stock-sync` 的「继承旧值」块里保留它们。

### 3.4 认领 / 作废 / 拆开三个动作（落库）

```ts
{ type:'claim-egg',     id: homeId, capturedEggId: bagId }  // 认领合并
{ type:'claim-dismiss', id: homeId }                        // 这颗不在了（作废）
{ type:'claim-split',   id: homeId }                        // 拆开认领
```

`claim-egg` 的校验（准确度优先，宁可不合）：

- 两行都属当前账号、`gameAccountKey` 相同；
- 家蛋行 `location === 'home'` 且 `claimPending === true`；背包行 `location === 'bag'`、`id === capturedEggId`；
- **物种必须相同**，否则报「物种不一致，不能认领」；
- 两行 `status === 'available'`（换蛋中的蛋先取消任务，避免把已占用的蛋合掉）。

合并结果（与 E2 里自动合并的字段口径一致）：

| 字段 | 取值 |
|---|---|
| `id` | **保留家蛋 id**（后续同步靠它再认） |
| `parents` / `provenance` / `greenNest` | 保留家蛋侧（自产标记不被 `unknown` 冲掉） |
| `nature` / `body` / `voice` | 背包值非空才覆盖（并先写进 `claimBackup`） |
| `obtainedAt` / `heightCm` / `weightGrams` / `itemConfId` | 取背包值 |
| `location` / `status` / `listed` | `'bag'` / 背包的 status / 重算（之后仍走 `autoListStock`） |
| `capturedEggId` | 背包实例 id |
| `claimPending` / `claimArrivedAt` | 清掉 |
| 背包那一行 | **删除**（同一颗蛋不能留两份） |

`claim-split`（拆开）：

- 家蛋行：`nature/body/voice ← claimBackup`，清 `obtainedAt/heightCm/weightGrams/itemConfId/capturedEggId/claimBackup`，`location ← 'home'`，`claimPending ← true`；父母、自产、绿窝照旧；
- 背包行：用 `id = capturedEggId` 重建，拿回时间/蛋重/蛋高/`itemConfId`/性格，`body/voice` 置 `unknown`、`provenance ← 'unknown'`、`claimArrivedAt` 记为当前时间；
- 说明：`body/voice` 置空是**故意的**——那两项合并时可能来自家蛋推算，不能算成背包实测；下一次背包抓包会自动补回真实值。

## 四、合并后卡片怎么变 / 撤销

- **蛋仓里**：待认领那张（虚线 + 「待认领」，无时间无蛋重）和背包新卡（有时间无父母）**合成一张**：绿框（绿窝）或普通框、左上「自产」、时间位变成获得时间、详情里有父母 + 蛋重 + 蛋高 + 真实性格。
- **计数**：横幅「有 N 颗」减一，减到 0 横幅消失；不再有待认领卡。
- **撤销**：蛋详情 → 「已与家园蛋 …1002 认领合并」→「拆开认领」→ 确认框讲清结果 → 两张卡都回来（家蛋待认领 + 背包新卡），父母/自产/时间/蛋重都不删。**明确支持撤销**，不是「暂不支持」。
