# Hindsight 长期记忆 · 使用与复盘规范（2026-11-28）

> 服务：`hindsight-api` 1.3.0，`http://127.0.0.1:8888`，开机自启。
> 接入方式：MCP bundle `@local/hindsight-mcp`（**不用** `dsh-hindsight` 插件，那个需要 DSH 0.3+ 的 API）。
> 工具：`mcp__hindsight__recall / remember / reflect / list / related / status`（无斜杠命令，只能由我调用）。

## 一、什么该记（写进去的价值）

**该记**（跨会话仍然成立、下次能省事）：

- 用户口径与偏好：「结论先行、≤3 选项带推荐、反感反复确认」
- 领域规则：「绿窝 = 任一亲本在学院小窝」「自动挂出要五项齐全」
- 结构性决定：「只有助理能发版」「stock-sync 不吃组级版本号」
- 事故与教训：「从落后 release 发版会回退 117 个提交」
- 人的信息：谁是组员、哪个 UID 属于谁（注意隐私，别记密钥）

**不该记**：

- 临时状态：「现在正在改 bind 引导」——一天后就错
- 能从仓库直接查到的事实：提交号、文件行号、测试数量（**会漂**，以 `git log` 为准）
- 一次性的对话细节、失败尝试的中间过程
- 任何密钥 / token / 密码

## 二、怎么写（决定了以后能不能召回）

```text
✅ 「用户的游戏账号 UID 是 67606564 和 537809018，同一个人的两个号，绑在同一个小组账号下」
✅ 「结单规则：必须双向确认（receive + confirm-return），双方各 +1 次免费领蛋」
❌ 「用户偏好简短回复」（太虚，抽取不出事实；实测这种只回 5 个 token、0 条事实）
```

**经验**：给**具体名词、具体数值、具体规则**；一句话只讲一件事；带 `context`（如「账号绑定」「蛋仓规则」）。

标签约定（`tags`）：

| 标签 | 用途 |
| --- | --- |
| `口径` | 产品规则、用户偏好 |
| `事故` | 出过的问题与教训 |
| `领域` | 洛克王国的孵蛋/蛋仓规则 |
| `流程` | 发版、审查、协作规范 |

## 三、复盘节奏（已写进定期汇报）

每次「项目进展汇报」（周一/三/五/日 09:00）里固定加一步**记忆复盘**：

1. `recall` 抽查 5~8 条与本周工作相关的记忆；
2. `list` 找**重复**（同一件事记了两三遍）、**过时**（规则已改）、**矛盾**（两条互相打架）；
3. 处理：
   - 重复 → `remember` 一条更准的，然后 `invalidate` 旧的（可恢复，不物理删）
   - 过时 → `invalidate`，并在新记忆里写清「取代了什么」
   - 错误 → `update` 修正
4. 结果写进 `docs/项目记忆/记忆复盘-YYYY-MM-DD.md`（≤15 行：新增/合并/作废/待确认各几条 + 具体条目）；
5. 若记忆库明显偏空或偏旧，补 3~5 条本周关键口径（**带出处**：文档路径或提交号）。

## 四、健康度基线（每次复盘顺手看一眼）

```
mcp__hindsight__status   → 服务健康
mcp__hindsight__get_bank → 库的 disposition 与 mission
```

判断「记忆有没有用」的三个信号：

| 信号 | 说明 |
| --- | --- |
| 召回命中率 | `recall` 出来的东西有 2 条以上真的用上了 |
| 重复率 | 同一事实在库里出现 ≥2 次 → 该合并 |
| 过时率 | 复盘中判为过时的条数 / 总抽查数 > 20% → 说明记太细了 |

## 五、当前已知限制

- **没有斜杠命令**（`dsh-hindsight` 插件在 DSH 0.2.2-rc.5 上装不了），只能由我在对话里调用工具；
- 因此「主动记忆」依赖我在合适的时候调用，复盘是兜底机制；
- 本地 embedding 模型是 `BAAI/bge-small-en-v1.5`，中文召回质量低于英文，**中文查询尽量带关键词**（如「UID 67606564」而不是「那个号叫什么」）。
