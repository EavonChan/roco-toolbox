## 2026-11-22 21:30 · 助理单入口，实现任务拆会话

- **决定**：用户只跟 A（助理）对话；A 负责判断何时开新会话、派什么任务、收什么结果。实现类工作进独立会话（P2/C1/S*），每轮结束把结论回写到 `docs/项目记忆/`。
- **替代**：用户自己盯 5~6 个会话；或全部塞进一个大会话。
- **为什么**：用户要"入口一致、负担更小"；大会话上下文会撑爆，而多会话自己盯太耗注意力。
- **影响**：A 的上下文只用于协调与决策；具体实现不再由 A 直接写。

## 2026-11-22 21:20 · 暂不建 RAG

- **决定**：现在不上向量库/知识库，用「现状 + 决策 + 用户画像 + 台账」四份活文档代替。
- **替代**：本地 embedding + 向量检索；或全文检索服务。
- **为什么**：项目只有 60 来份文档，高频要用的不到 5 份；RAG 检索"相似"，但项目里要的是"权威"（今天交接文档的数字全是旧的，语义检索会把过期文档排前面）。
- **影响**：重启条件写进本次记录——文档 >300 份、需要跨会话语义检索、或 A 每月因找不到而重复劳动 ≥2 次，再考虑；届时先用 SQLite FTS，不上向量。

## 2026-11-22 21:15 · 装跨会话工具

- **决定**：安装 `@laoyuehanni/dsh-session-tools`（读写/发送/新建会话）与官方 `@deepseek-ai/dsh-experimental-session-search`（只读检索）。
- **替代**：继续用脚本解压 `~/.dsh/sessions/*.jsonl.zstd`。
- **为什么**：DSH 官方明确不建议直接读 jsonl（绕过授权与 compaction 层）；插件走 `session.prompt` 准入与投影层。
- **影响**：A 可直接给会话发消息/接收回信；需重启 DSH 生效；第三方插件拿到跨会话读写权限（已告知用户）。
