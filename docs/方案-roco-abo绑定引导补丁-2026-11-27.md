## 1. 前置：服务端已经回 `code`（本仓库，已提交）

`functions/_lib/eggBotBridge.ts` 的两处 `ingest` 拒绝现在多一个机器可读字段，`error` 原句保留：

```json
{ "ok": false, "code": "group-unbound", "error": "这个群还没接入换蛋提醒" }
{ "ok": false, "code": "uid-unbound",   "error": "这个 UID 还没绑定到小组成员" }
```

> 旧机器人不受影响：`msgspec.json.decode(..., type=Reply)` 默认**忽略未知字段**，
> 不升级的机器人照旧只读 `error`，显示原文。

## 2. 机器人要改的两个文件（约 12 行）

源码位置（本机）：`D:\QQBot\gsuid_core\gsuid_core\plugins\RocomUID\RocomUID\`。
该插件目录**没有 `.git`**（见 `docs/分析-机器人代码审计与改代码权限-2026-11-22.md` §2），
所以改前先备份这两个文件。

### 2.1 `rocom_toolbox/bridge.py`：`Reply` 加一个字段

```python
class Reply(msgspec.Struct):
    ok: bool = False
    error: str = ''
    code: str = ''          # ← 新增：'group-unbound' / 'uid-unbound' / ''（旧服务端不回）
    uid: str = ''
    ...
```

只加字段、不动 `call()`：非 200 与解析失败仍走原来的通用文案。

### 2.2 `rocom_homeinfo/egg.py`：`note` 按 code 选文案

现在（`egg.py:118-119`）：

```python
        else:
            note = f'，蛋仓未同步（{reply.error}）'
```

改成「短句 + 一次完整路径」，避免多 UID 时每条都刷一遍长句：

```python

_BIND_PATH = '绑定路径：小布助手 → 我的 → 我的小组 → 我的资源 → 点「绑定游戏账号」，勾上这个号后发布。'

# ...（同函数内）
        else:

                reply.code, reply.error or '小布助手暂时没返回原因'
```

### 2.3 多 UID 时只在末尾附一次路径

`rocom_homeinfo/__init__.py` 的「不带参数的 `rc生蛋了吗`」会把每个 UID 的那段拼在一起
（`egg.py` 返回的 `lines` 逐段 join）。在那里判断：本批里只要出现过 `uid-unbound`，
就在整段末尾追加一次 `_BIND_PATH`。

实现上二选一（推荐 B，改动面小）：

- **A**：`api_to_home_egg_text()` 额外返回一个 `unbound: bool`，调用方汇总后在末尾加路径；
- **B**：`api_to_home_egg_text()` 里把路径记进一个模块级集合 / 用返回值字符串匹配
  `'还没在小组里绑定'`，调用方拼接完再统一追加一次。

> 文案里**不要写死按钮以外的界面位置**（按钮已经改名成「绑定游戏账号」；
> 「我的 → 我的小组 → 我的资源」这三层短期不会变）。

## 4. 部署方式（待确认，所以本轮没动）

机器人是自己机器上的本地副本，没有 git、没有 CI，**改完必须重启 gsuid_core 才生效**；
重启会中断正在跑的定时推送。需要先确认：

1. 由谁改、由谁重启（本机副本 vs 新开 `bot/plugin` 分支，见审计文档 §7）；
2. 改前是否 `git bundle`/复制备份；
3. 是否先在**测试群**（`RC_bridge_test_groups`）验证第 1–5 条，再切正式群。
