# 组件库建设指南（2026-11-22）

> 起因：原型基准重建会话阶段 0 的产出「看起来还是乱」。本文件先给行业做法，再给针对我们产出的诊断与改造方案。
> 适用：P2 会话、后续所有 UI 方案、以及代码侧 `src/ui/primitives` 的沉淀。

## 一、先看结论

乱**不是排版问题，是结构问题**。三个具体症状：

| 症状 | 证据 |
| --- | --- |
| **一张卡一个实现** | 精灵卡家族 7 种卡，高度有 **5 个不同值**：98 / 104 / 104 / 106 / 96 |
| **token 只有一层** | `tokens.css` 174 个变量，全部是「调色板原值」（`--c-slate-500`）＋少量尺寸，**没有语义层**，所以"只许引用变量"仍然挡不住随意选色 |
| **工具与产物混住** | `_shared/` 里同时躺着 `tokens.css`（产物）和 9 个 `.mjs`（工具） |

## 二、行业做法（只取可抄的）

### 1. token 分三层，不是一层调色板

Ant Design 5 的官方模型是 **Seed → Map → Alias** 三层派生：Seed 是设计意图（如 `colorPrimary`），算法派生出 Map（各级色阶），Alias 再映射到用途（如 `colorLink`）。组件还有自己的 **Component Token**，可以只覆盖某个组件而不影响别人。

- 来源：[Ant Design · Customize Theme](https://ant.design/docs/react/customize-theme)

我们要补的正是中间那一层：

```
① primitive（原值）    --c-slate-500: #64748b      ← 现在只有这层
② semantic（用途）      --text-secondary: var(--c-slate-500)
                      --surface-card: var(--c-white)
                      --border-subtle: var(--c-slate-200)
③ component（组件）     --pet-card-height: 104px
                      --pet-card-avatar: 44px
                      --pet-card-name-size: 12px
```

规矩：**页面只许用 ②③，②③ 只许引用 ①**。这样换主题只改 ①，调某个组件只改 ③。

### 2. 组件文档是四件套，不是一页长滚动

Carbon 的组件贡献模板固定四个页签：**Usage（何时用/何时不用）、Style（anatomy、尺寸、状态）、Code（API）、Accessibility**。每个组件都按这个骨架写，不允许只有"看起来是这样"的截图。

- 来源：[Carbon Design System · Contributing components](https://carbondesignsystem.com/contributing/component/)

对应到我们：一个组件一个目录、一个 `spec.html`（只放这一个组件）、一份 README（八段，见 §五）。

### 3. 一个组件 × 多个 variant，不是多个组件

行业里"卡片"从来不是 7 个组件，而是 **1 个 Card + size/variant/state 三个维度**。
判断标准很简单：**如果两个"卡"的差别只有高度、字号、有没有底栏，那它们就是一个组件的 variant。**

### 4. 命名按用途，不按外观

`color.action.primary` 而不是 `color.blue`；`spacing.layout.gutter` 而不是 `spacing.16`。
Design Tokens 社区规范（DTCG）把这种"引用别名"写进了格式标准：值写成 `{color.gray.50}` 时在构建期解析成引用，原值一变、引用自动跟着变。

- 参考：[Design Tokens Format Module（DTCG）](https://www.designtokens.org/TR/2025.10/format/#aliases-references)

我们现在的 `--c-slate-500` 属于 ①，没问题；问题是**没有 ②**，所以每个页面都在直接挑色阶。

## 三、我们现状的诊断（逐项对得上文件）

| 项 | 现状 | 结论 |
| --- | --- | --- |
| token 层数 | 1 层（174 个原值 + 少量尺寸） | 缺语义层与组件层 |
| token 校验 | 34 条对账（16 色 / 8 字号 / 4 圆角 / 4 控件高 / 1 阴影 / 1 容器宽） | ✅ 这块做得好，保留 |
| 卡片 | 7 种、5 个高度 | 需要收敛成 1 组件 × 2 尺寸 × 7 变体 |
| 文档 | README 一页 19 KB 长滚动 + 底部 bullet 规格 | 拆成每组件一份八段文档 |
| 目录 | 产物与工具混在 `_shared/` | 按 `_components / _pages / _tools / _baseline` 分层 |
| 尺寸来源 | 规格表里手写「98px / 106px / 104px」 | 应改为引用 `--pet-card-height-*` |

## 四、目标目录结构

```
原型/设计稿/
├─ README.md                  索引 + 使用说明（只放导航，不堆规格）
├─ _tokens/
│   ├─ primitive.css          ① 原值（调色板、字号阶、间距阶）
│   ├─ semantic.css           ② 用途（文字/底/描边/状态色）
│   └─ component.css          ③ 组件（卡片高度、头像尺寸、控件高）
├─ _shell/                    外壳（只有一份；HTML + CSS + JS）
├─ _tools/                    脚本（截图 / 对账 / 自检 / 视觉回归）
├─ _baseline/                 基准截图（375 / 390，含登录态）
├─ components/                ★ 组件库
│   └─ pet-card/
│       ├─ README.md          八段文档（§五）
│       ├─ spec.html          只放这一个组件的全部 variant/state
│       └─ pet-card-{375,390}.png
└─ pages/                     ★ 页面级设计稿（只引用 components，不复制样式）
    └─ dashboard/
        ├─ README.md
        └─ index.html
```

关键：**components 与 pages 分开**。页面里允许出现"这个页面特有的组合"，但组件本身的样式只能来自 `components/`。

## 五、组件文档八段模板

每个 `components/<name>/README.md` 必须八段齐全，缺一段算未完成：

1. **一句话定义**：它是什么、给谁用。
2. **何时用 / 何时不用**：附反例（"这里应该用 X 而不是它"）。
3. **Anatomy**：编号图 + 每个部件叫什么（如 头像 / 名字 / 蛋组 / 性格 / 底栏）。
4. **Variants**：列出全部变体，每个配 375 截图。
5. **States**：default / hover / selected / disabled / empty / loading，各一张。
6. **Do / Don't**：各三条，配图。
7. **Token 引用表**：这个组件用了哪些 ②③ 变量（不允许出现裸 hex）。
8. **代码位置**：`src/ui/xxx.tsx:行号` + 对应的 props 签名。

## 六、精灵卡家族收敛方案（具体建议）

现在：

```
种公推荐 98px ｜ 母本 106px ｜ 缺口 104px ｜ 背包 104px ｜ 紧凑卡 160×98 ｜ 堆叠 96px ｜ 需求卡(高未定)
```

建议收敛成 **两个尺寸档 + 七个变体**：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| size | `sm` 96px / `md` 104px | **已确认（2026-11-22，用户拍板）**：母本卡 106 合并到 104 |
| variant | `stud-recommend` / `mother` / `gap` / `inventory` / `compact` / `stack` / `demand` | 语义名，不叫"卡1卡2" |
| state | `default` / `hover` / `selected` / `disabled` / `empty` | 状态是组件的属性，不是另做一张卡 |

落地到代码就是一个组件：

```tsx
<PetCard size="md" variant="gap" state="default" />
```

布局由 `--pet-card-height-sm/md`、`--pet-card-avatar`、`--pet-card-name-size` 驱动，组件内部不写死像素。

**尺寸决策已定**：96（sm）/ 104（md）两档，母本卡由 106 改为 104。变更记录写进组件 README 第 6 段的「Do / Don't」附近，注明"2026-11-22 合并，原 106px"。

## 七、质量门禁（可执行，不靠自觉）

| # | 规则 | 检查方式 |
| --- | --- | --- |
| 1 | 组件高度只能取 token 枚举值（96 / 104） | 脚本扫 `components/**/*.css` 与 spec.html，出现其他高度即 fail |
| 2 | 禁止裸色值 / 裸字号 | `grep -E '#[0-9a-f]{3,6}|font-size:\s*\d+px'` 命中即 fail |
| 3 | 每个组件目录必须齐 README + spec.html + 2 张截图 | 目录断言脚本 |
| 4 | spec.html 里每个 variant 必须有对应 state 截图 | 人工 + 截图命名约定 |
| 5 | 页面级设计稿与基准截图的差异必须能逐条解释 | 视觉 diff + 差异清单 |
| 6 | `tokens.css` 每次改动都要与线上重跑对账 | 复用现成的 `verify-tokens.mjs`（34 条） |

前 3 条可以立刻写成脚本（P2 已有 `verify-tokens.mjs` / `check-shell.mjs` 的基础）。

## 九、行业案例清单（想深挖时看这些）

| 系统 | 值得抄的点 |
| --- | --- |
| [Ant Design](https://ant.design/docs/react/customize-theme) | Seed/Map/Alias 三层 token + 组件级 token 覆盖 |
| [Carbon](https://carbondesignsystem.com/contributing/component/) | 组件文档四件套（Usage/Style/Code/Accessibility） |
| [Material Design 3](https://m3.material.io/foundations/design-tokens/overview) | ref/sys/component 三层命名与"语义不写外观" |
| [Atlassian Design System](https://atlassian.design/components) | 组件 + token 双索引，找东西快 |
| [Polaris](https://polaris.shopify.com/components) | 每个组件都给"何时别用"的反例 |
| [GOV.UK Design System](https://design-system.service.gov.uk/components/) | 每个组件都写着用户研究结论与无障碍要求 |
| [shadcn/ui](https://ui.shadcn.com/) | 代码即文档：组件源码就是规范，靠 CSS 变量换主题 |

> 说明：Ant Design 与 Carbon 的要点已按官方文档核对；Material 3 与其余几个仅作索引，具体条目以各自站点为准。
