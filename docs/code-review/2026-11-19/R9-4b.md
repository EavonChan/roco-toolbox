## R9-4b-M01 · 中风险 · 公开包打开「服务器地址」面板时，当前所在的正式站被标成「测试服（默认）」，同一地址同时出现在「默认：测试服」和「正式：正式服」两行

① 问题描述：现状是面板用「当前地址 == 壳给的默认地址」来判断当前是测试服，并把「默认」一行硬编码标成「测试服」；公开包的默认站就是正式站，所以正式用户会看到正式地址被称为测试服；用户影响是排障时无法判断自己到底在哪个站，误以为需要切换，切错后按 origin 隔离的本地身份会变；触发条件是公开包连点版本号 5 次（公开包无内置测试站，`toggle()` 返回失败后自动打开面板）。
（`src/ui/ServerAddressPanel.tsx:138-140` `currentKind` 与 `:163-167` 默认行文案；`android-shell/.../ServerConfig.java:27-28,94-96` `defaultUrl()` 返回 `BuildConfig.DEFAULT_SERVER_URL`，公开包即正式站；`ServerConfig.java:111-120` 公开包 `toggle()` 返回失败提示）

② 优化方案：标签按地址与 `productionUrl` 的真实关系推导：`current === productionUrl → 正式服`，`current === defaultUrl && defaultUrl !== productionUrl → 测试服（默认）`，其余「自定义」；默认行文案同规则（默认=正式时写「正式服（默认）」）。约 6 行 + 测试用例；风险极低，不涉及壳。

③ 优化后表现：解决「正式站被标成测试服」；验收：`npx vitest run src/ui/ServerAddressPanel.test.tsx`，补「公开包（defaultUrl=productionUrl）→ 当前显示正式服」用例。

## R9-4b-M02 · 中风险 · 内测包一键切到打不开的站点后，网页加载失败只剩一句 toast，没有任何原生入口能切回来

① 问题描述：现状是一键互切对自家两个地址「不探活、直接写」，切完立即重载；若目标站当时打不开，WebView 停在系统错误页，壳只弹一次「打不开网页，请检查手机网络后重试」，而切换入口在网页的版本号上，此时根本点不到；用户影响是内测人员被锁在打不开的客户端里，只能清应用数据或重装才能回到可用站点；触发条件是切到的一方站点故障/被墙/证书异常。
（`android-shell/.../ServerConfig.java:103-120`（注释称「连点一次就能切回来」）、`MainActivity.java:294-300`（主文档错误只 toast）、`:829-840`（`applyServer` 保存后重载）；网页侧无原生兜底调用）

② 优化方案：在壳的主文档加载失败分支提供一个原生恢复入口（AlertDialog：切到默认站 / 切到正式站，调用 `serverConfig.reset()/toggle()` 后重载），或长按返回键触发同一入口。约 40 行 Java，不改网页；代价是需要重新构建 APK 才能生效，网页侧本轮无法兜底。

③ 优化后表现：解决「切错站点后无法自救」；验收：`cd android-shell; ./gradlew test`（补 `ServerConfigTest` 的恢复用例）+ 真机把地址改成不可用域名，确认能弹原生恢复并切回。

## R9-4b-L01 · 低风险 · 网页注释写「服务器地址只在内测壳里存在」，但公开包也注册了同一个桥，连点会打开手动面板

① 问题描述：现状是 `ServerBridge` 的注释和 `Profile.tsx` 的注释都说入口只在内测壳存在，实际 `RocoServer` 在所有通道都注册，公开包连点会走「失败提示 + 打开面板」分支；用户影响仅限后续维护者，按注释会误判正式包没有这个入口；触发条件是读代码/排障。
（`src/ui/ServerAddressPanel.tsx:4`、`src/ui/Profile.tsx:57`；`MainActivity.java:252-253` 无条件 `addJavascriptInterface(serverBridge, "RocoServer")`；`ServerConfig.java:21-23` 的类注释描述的是真实行为）

② 优化方案：把两处注释改成「浏览器没有桥，公开包有桥但无内置测试站地址，连点会提示并打开手动面板」。一行改动，无行为变化。

③ 优化后表现：注释与壳端行为一致；验收：人工核对。

## R9-4b-L02 · 低风险 · 面板里点「保存」后 30ms 内收起，探活结果会丢，用户不知道地址到底存没存

① 问题描述：现状是保存/恢复都在 30ms 延时里调同步桥，组件被收起（`onClose`）后仍然执行 `setNotice`，但节点已卸载，失败原因看不见；成功时壳会重载页面，问题不大，失败时用户以为已经保存；触发条件是点保存后立刻点「收起」。
（`src/ui/ServerAddressPanel.tsx:105-123`、`:207-215`；同步桥最长阻塞 5 秒）

② 优化方案：`busy` 时禁用「收起」，或在 `run()` 里把结果同步到上层（`onNotice`）由 Profile 展示。约 5 行；风险低。

③ 优化后表现：失败原因不会因收起而丢失；验收：`npx vitest run src/ui/ServerAddressPanel.test.tsx`。
