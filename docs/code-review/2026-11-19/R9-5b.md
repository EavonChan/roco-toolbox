## R9-5b-M01 · 中风险 · 教程进度的跨站同步从没启动：升级后切服，教程仍会重弹

① 问题描述：现状是共享偏好层写好了「把本环境已有的已读进度灌进壳」的 `syncTourSeen()`，但全仓没有任何调用方；用户影响是升级到本版后，已有的「已看过教程」只存在当前站点 origin，切到另一个站时壳里没有记录、本地也没有，主线和各页签教程会重新弹一遍——这正是该模块要解决的问题；触发条件是用过旧版（教程已读只存在 localStorage）后切换服务器地址。
（`src/ui/tour.ts:243-246` `syncTourSeen` 定义，`git grep syncTourSeen` 仅命中定义处；读取路径 `:223-227` → `src/api/sharedPrefs.ts:69-89`，壳里无值时不回填也不上送）

② 优化方案：在 App 启动处（已有 `installFlushOnHide` 的 effect，`src/App.tsx:150-153`）加一行：`if (prefsBridge()) syncTourSeen();`，只在本机已有值和壳同时存在时执行；同时先修 R9-5b-L01，避免同步把旧值盖成最新。约 3 行；风险是每个页签启动多 6 次 localStorage 读写，可忽略。

③ 优化后表现：解决「切服后教程重弹」。验收：`npx vitest run src/api/sharedPrefs.test.ts`；真机在正式站看过教程 → 切到测试站 → 不再自动弹主线。

## R9-5b-M02 · 中风险 · 机器人连接失败时，接口返回 HTML 错误页会直接把英文解析错误抛给用户

① 问题描述：现状是 `eggPatrol` 先 `response.json()` 再看 `response.ok`，且错误只取 `data.error`，没有状态码、错误码与响应片段；用户影响是网关/代理返回 HTML 或空 body 时，界面出现 `Unexpected token '<'` 这类英文错误，用户不知道是网络、登录过期还是服务故障；触发条件是蛋巡查机器人接口 502/断网代理/未登录回退页。
（`src/api/eggPatrol.ts:5-12`；依据：同模块既有写法 `src/api/collectionGroups.ts:109-140`（先读 text → 解析 → 非 JSON 时带 method/url/status/content-type/片段）与 `src/api/eggMatching.ts:41-46`（`json().catch(()=>null)` 后统一文案））

② 优化方案：把 `request()` 改成与 `collectionGroups.request` 同构：`await response.text()` 后安全解析，非 2xx 用 `{error, code}` 统一成中文，2xx 非对象时给「响应不是接口数据（GET /api/.../egg-bot → 502 text/html，开头：…）」；三个接口的字段校验保持现状。约 25 行，错误文案会变化（需同步 `EggBotConnection` 的展示用例）。

③ 优化后表现：解决「机器人接口故障显示英文解析错误」。验收：`npx vitest run src/api/eggPatrol`（补一条 HTML 502 用例，断言中文文案含状态码）。

## R9-5b-L01 · 低风险 · 把本机进度同步进壳时会刷新时间戳，等于让「较旧的值」在同步那一刻变成最新

① 问题描述：现状是 `syncShared` = `readShared` + `writeShared`，而 `writeShared` 一定用 `Date.now()` 盖章；用户影响是一旦按 M01 接线，另一台/另一站点较新的进度会被这次同步覆盖成旧值（下次读到的就是旧进度）；触发条件是两个 origin 的已读版本不一致时的首次同步。
（`src/api/sharedPrefs.ts:92-110`；`syncShared` 复用 `writeShared` 的 `at = Date.now()`）

② 优化方案：给 `writeShared` 增加可选 `at` 参数（或新增 `writeSharedAt`），`syncShared` 先读出「本地 at 与壳 at 的较大值」再原样写入，不刷新时间戳。约 8 行；测试补「壳较新 + 本机旧值 sync 后仍读壳值」。

③ 优化后表现：同步只做搬家、不改变先后关系；验收：`npx vitest run src/api/sharedPrefs.test.ts`。

## R9-5b-L02 · 低风险 · 批量删除原包时个别失败也会清空全部勾选，且每删一个都整轮刷新一次状态

① 问题描述：现状是串联调用 `action('deleteCapture', id)`，`action` 内部吞掉错误只返回 false，循环结束后无条件 `setSelectedFiles(new Set())`；用户影响是删除失败的文件也从勾选里消失，得重新勾一次才能重试，而每个文件都会触发一次 1.5 秒轮询外的额外状态读取；触发条件是删除过程中壳返回失败（文件被系统清理、存储只读等）。
（`src/ui/NativeCollectorPanel.tsx:117-128`、`:140-151`）

② 优化方案：收集失败的 id，只把成功的从勾选里移除；循环结束后统一 `refresh()` 一次，`action` 提供「不自动刷新」选项或批量分支直接调 `collectorAction`。约 15 行；不影响单个删除路径。

③ 优化后表现：失败的原包仍在勾选里可重试；验收：`npx vitest run src/ui/NativeCollectorPanel.test.tsx`，补「两个文件一个失败 → 只保留失败项勾选」。
