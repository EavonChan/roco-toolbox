## R6a-H01 · 高风险 · 选了体型或声音档位后，性格 / 蛋组选项旁的命中数偏大，点进去却是空列表

① 问题描述：**现状** —— 背包的分面计数在传给 `computeFacetCounts` 之前，把「体型」「声音」两类已选条件**整类删掉**（不只是删对计数对象自己那一类），于是所有维度（性别 / 稀有 / 性格 / 蛋组）的数字都不再考虑用户已选的档位；而列表本身仍然叠加这一档。**用户影响** —— 例如背包里 10 只母、其中 4 只大块头，勾了「大块头」时「性格 · 开朗 (6)」仍写着 6，点下去列表却是 0 只，只剩「没有符合条件的精灵，试试取消部分标签」；性别 / 稀有 / 体型图标则会出现「没置灰但点出来是空」的死路。**触发条件** —— 先选体型或声音任一档位，再看其它筛选的数字或置灰状态（`MyPets.tsx:462-466` 把 `SINGLE_SELECT_KINDS` 从已选条件里剔除；而 `petFilters.ts:335-361` 的 `computeFacetCounts` 本来就按「不计被计数的那一类」处理，不需要再剔一次；对照 `779b08c` 版本同一处只剔 `account:`）。

② 优化方案：把传给 `computeFacetCounts` 的已选条件恢复成只剔 `account:`（即删掉 `SINGLE_SELECT_KINDS` 这段过滤）。「选了某档就看不到别的档还可选」的问题由 `computeFacetCounts` 自带的同类排除解决，不需要在页面层再剔。改动约 3 行，同时补一条断言：勾「大块头」后，性别 / 性格的计数应等于「再叠加该维度后列表的条数」。

③ 优化后表现：**解决** —— 每个筛选旁的命中数与它点下去得到的列表条数一致，不会再出现「写着 6 点开 0」。**验收** —— 造两只同性格、不同体型的精灵：只勾其中一档体型，打开性格面板，数字应为 1；点它，列表也是 1；再点另一档体型，同性格的数字仍应与列表一致。

## R6a-M01 · 中风险 · 双组模式下性格旁的命中数按「满足任一蛋组」统计，列表却只留「两个蛋组都满足」的精灵

① 问题描述：**现状** —— 「双组」模式下列表对两个蛋组取**交集**，但分面计数把两个蛋组当成同一类的普通多选，按**并集**算基础集合，于是性格 / 性别等选项的数字偏大。**用户影响** —— 用户按数字判断「这个性格还有 8 只符合两组的精灵」，点开只有 3 只，判断简历/挑母本时会误判；数字为 0 的项被置灰的情况也可能反过来（本可命中却显示 0）。**触发条件** —— 切到「双组」并选满两个蛋组后，查看任意其它维度的数字或置灰状态（`MyPets.tsx:443-450` 列表按 `eggGroupSets.every(...)` 取交集；`MyPets.tsx:459-469` 只把蛋组当普通一类传进 `computeFacetCounts`，其内部 `petFilters.ts:340-353` 按并集计算）。

② 优化方案：方案 A（推荐，改动小）——给 `computeFacetCounts` 增加一个「某类按交集」的选项（例如 `intersectingKinds: ['eggGroup']`），双组模式下传入；方案 B ——在页面层先用两组交集得到 `withinIndices` 再单独算一次蛋组自身以外的计数，需要额外维护两套结果，后续易漂。推荐 A，并加一条「双组 + 性格」的计数与列表一致性断言。

③ 优化后表现：**解决** —— 双组模式下每个数字都对应真实结果数。**验收** —— 用一只同时具备两组、一只只有第一组的精灵：双组勾两组后，两只共有性格的数字为 1，点开列表也是 1；切回多选时数字恢复为 2。

## R6a-M02 · 中风险 · 命中数为 0 的性格选项照样能点，点了只得到空列表（同面板的蛋组选项此时是灰的）

① 问题描述：**现状** —— 性格面板由页面自己渲染按钮（`renderNatureOption`），没有传 `disabled`，所以「(0)」的性格按钮仍可点击；同一面板里的蛋组选项走 `filterDimensions`，命中 0 且未选中时会被置灰。**用户影响** —— 同一块筛选面板里两套规则：性格可以点出空列表、蛋组点不动，用户会以为自己漏选了什么；选到 0 命中性格后列表变空，还得再点一次取消。**触发条件** —— 任意已有筛选使某性格命中为 0 时打开性格面板（`MyPets.tsx:545-565` 的 `renderNatureOption` 无 `disabled`；对照同文件 `:747` 蛋组选项 `disabled: ((facetCounts[tag.id] ?? 0) === 0 && !on) || limitReached`；`779b08c` 版本走 `FilterAccordion` 时也有同款置灰）。

② 优化方案：在 `renderNatureOption` 上补与蛋组一致的 `disabled = (count === 0 && !on)`，并在按钮上加 `disabled:opacity-40` 一类样式；「已选但命中 0」仍保持可点，避免删不掉。改动集中在 3 行属性。

③ 优化后表现：**解决** —— 性格与蛋组的可点规则一致，点不出空列表。**验收** —— 勾一个只命中 3 只精灵的稀有度，再打开性格面板：没命中的性格呈灰色不可点，已选的性格仍可点掉。

## R6a-L02 · 低风险 · 导入了 0 只精灵、或把账号全取消时，页面让用户「取消部分标签」——但标签不是原因

**3. R6a-M01（双组模式计数按并集）**
① 现状：列表对两个蛋组取交集，计数按并集；用户影响：数字偏大、挑母本误判；触发：双组 + 两个蛋组后再看其它维度。（`MyPets.tsx:443-450` 与 `:459-469`）

③ 表现：解决——双组下数字与列表一一对应；验收——两只精灵的样例里，共有性格数字为 1、点开也是 1。
