## 三、问题

### R3b3-H01 · 高风险 · 小组里再也发不了需求、接不了单、也找不到「共同寻找」

**① 问题描述**
- **现状**：小组页现在只渲染换蛋中心（`我的收集 / 组内广场 / 蛋仓 / 我的换蛋`），旧「我缺的、需求中心、共同寻找」三页随 `MotherGroupResources` 的最后一个挂载点一起不可达。
- **用户影响**：进小组页后无法再发布母本需求、无法接别人的单、无法认领/释放/转交共同寻找任务；已在首页「接单上窝」里出现的历史接单还能收尾，但接不到新单，也没地方发新需求——而 `docs/产品交互规范.md:126`、`:135`、`:154` 仍把这三页写成现行口径。
- **触发条件**：任何已登录的小组用户进入「小组」页即可复现（`src/App.tsx:250-255` 只挂 `CollectionGroups`；`CollectionGroups.tsx:394` 只挂 `GroupPlanHub`；`GroupPlanHub.tsx:5` 只渲染 `EggMatchingHub`；`EggMatchingHub.tsx:231-234` 仅有收集/广场两个页签与两个工具入口；`MotherGroupResources.tsx:2483`、`:2490`、`:3610-3646` 的需求中心/任务 UI 现存唯一挂载点 `MotherSharing.tsx:190` 本身也没有任何页面挂载）。

**② 优化方案**
需要业务口径二选一，先别改代码：
A **确认下线**：把 `MotherGroupResources`、`MotherSharing` 及其 4.5k 行与测试一并处置（或明确标为历史），同步改 `docs/产品交互规范.md:126/135/154`，并决定首页「接单上窝」与附近「需求」筛选取数是否一起停（它们仍读 `collection_group_demands`：`HomeDemandPlacements.tsx:165`、`useCollectionGroups.ts:435`）。
B **保留能力**：在小组页给需求中心留一个整屏二级入口（沿用旧 `legacyView` 式进入方式，只承载需求中心/共同寻找，不恢复计划卡），改动集中在 `EggMatchingHub` 外再挂一个入口按钮，代价是小组页多一层跳转。
推荐 B，除非本次发版已明确「需求中心不再提供给用户」——因为 `useClaimedDemands` 与附近需求筛选仍在消费同一份数据，只删入口不删能力会让数据「只进不出」。

**③ 优化后表现**
- **解决**：用户要么明确知道需求中心已取消（并且不再看到需要它才能处理的数据），要么还能进得去。
- **验收**：A — 小组页、首页、附近三处不再出现任何「需求」字样与依赖该数据的按钮，`文档口径同步`；B — 小组页点「需求中心」能进入并可发布/接单/认领，`npx playwright test e2e/mother-sharing.spec.ts` 恢复通过。
