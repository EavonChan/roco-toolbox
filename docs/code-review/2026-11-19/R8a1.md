## R8a1-H01 · 高风险 · 反复开关附近面板后，手机内存一路上涨、每次展开地图都要先空白一下

**① 问题描述**
现状：每次展开面板都新建一个地图网页视图，收起时只把窗口和子视图摘掉、**从不销毁**这个网页视图，下一次展开又在 `buildMapBox()` 里 `new WebView` 覆盖字段，旧实例失去引用但没有走 `destroy()`，整个类里唯一的销毁点是 `release()`。
用户影响：真实使用中「点球展开 → 收起 → 再展开」累积若干次后，每个遗留网页视图都还压着一份网页渲染资源，低端机表现为悬浮层变卡、偶发被系统回收；同时因为不是复用，每次展开都要重新加载地图页，展开瞬间地图区先深色空白一下。
触发条件：任何一次收起后再展开（游戏中进行采集即可复现）。
（证据：`NearbyPanelController.java:539-549` 每次 `buildMapBox → createMapView → new WebView`；`:551-616` 加载 `overlay-map.html`；`:388-413` 收起只 `removeAllViews`，不置空/不销毁 `mapView`；`:618-629` `destroyMap` 仅由 `:381-386 release()` 调用。）

**② 优化方案**
二选一。A（推荐，真复用）：收起只摘窗口，保留 `mapView` 与 `mapBox`，下次展开把原实例挂回去，只有 Activity 销毁或渲染进程回收时才销毁重建。B（改动更小）：收起即销毁并显式清空字段，展开时重新加载，同时接受闪白。A 约 40 行改动，需处理重新挂载后的尺寸变化；B 约 10 行，行为更直白。两种方案都必须保证 `release()` 之外不再有第二个「只摘不销毁」的出口。

**③ 优化后表现**
解决：开关面板不再累积网页视图，内存曲线持平；展开时地图沿用上一帧或稳定重建，不再长时间空白。
验收：真机采集状态下连续开关面板 20 次，`adb shell dumpsys meminfo <包名>` 的 Java Heap / Native Heap 不单调上涨。

## R8a1-M01 · 中风险 · 面板展开时每秒最多 4 次全量重排，地图数据整份重灌

**① 问题描述**
现状：网页每推一帧附近数据（约 1 次/秒、最快 250ms 一次）就完整渲染一遍：重新构造两张背景、逐个重设命中区/标题/地图/列表/脚注的位置并 `updateViewLayout`，再把整份地图点 JSON 通过 `evaluateJavascript` 注入地图页；列表已有「内容签名不变就跳过」的保护，地图与容器没有对应处理。
用户影响：面板展开时游戏画面上叠加一层持续重排与跨线程脚本注入，低端机表现为面板文字/列表轻微掉帧、机器发热；地图页每帧还重写每个点的样式，与「刷新只改 transform」的注释目标不一致。
触发条件：采集进行中、面板展开、附近精灵在移动（payload 持续变化）。
（证据：`NearbyPanelController.java:664-764` 每帧 `setBackground` `:686-687`、`setFrame` `:702/:720/:732-738/:753`、`pushMapData` `:756`；签名跳过只覆盖列表 `:740-748`；地图注入 `:975-1012`；`assets/overlay-map.html:263-293` 每帧重写点的 className/left/top/innerHTML。）

**② 优化方案**
把列表的签名思路推广到面板整体：算一个包含行数、命中区文案、地图点集合、显隐与尺寸的签名，签名不变只做必要的尺寸更新，不重设背景与帧位置；地图推送改成「自身坐标变化 > 1 或点位集合变化」才注入。地图页把 `innerHTML` 只在稀有/提醒状态跳变时写一次，其余帧只改几何。
代价：约 60~80 行改动，需要确认面板高度缓存与签名覆盖字段完整；依据是「同模块既有写法」——`:740-748` 已用签名保护列表，本项只是把同一保护补到地图与容器。

**③ 优化后表现**
解决：面板内容没变时零重排，地图注入次数从每秒数次降到「坐标真正变化时」。
验收：真机 `adb logcat -s RocoPerf` 中面板静止时 `render` 计数与 `mapPush` 计数不再随 `payload` 同比例增长。

## R8a1-M02 · 中风险 · 悬浮窗权限被收回或加窗失败时，点球完全没反应、也没有任何提示

**① 问题描述**
现状：`addPanel()` 的 `windowManager.addView` 失败时只回滚字段并把 `expanded` 置回 false，不记录原因、不回报网页，`toggle()` 因此静默结束；而同一模块的战斗球在没有权限时会明确回 `need-permission`，让页面给出授权入口。
用户影响：权限被系统收回或厂商系统拒绝加窗时，用户点球看不到面板，页面也不会出现「去授权」按钮，只会以为悬浮窗坏了。
触发条件：采集进行中，在系统设置里关闭「显示在其他应用上层」后返回游戏点球（或个别厂商 ROM 拒绝往非 Activity 窗口加子窗口）。
（证据：`NearbyPanelController.java:459-466` 失败仅回滚；`:231-240` `toggle()` 无返回值、无失败分支；对照 `BattleOverlayController.java:216-219`、`:233-238` 的 `need-permission` 语义。）

**② 优化方案**
让展开路径与战斗路径统一：`addPanel` 失败时把「需要授权 / 加窗失败」带回 `toggle()`，由 `BattleOverlayController.updateNearby` 像 `update()` 一样返回 `need-permission`（或专门失败码），网页侧沿用现有授权按钮；同时把失败原因写进 RocoPerf 便于真机排查。约 20 行，不改协议；旧网页收到未知返回值时按现有「非 unsupported 即成功」处理，无兼容风险。

**③ 优化后表现**
解决：权限异常时用户能看到授权入口，而不是点了没反应。
验收：真机采集状态下关掉悬浮窗权限，回到游戏点球，页面出现对应授权提示。

## R8a1-L01 · 低风险 · 注释承诺「收起后下次复用地图」，实现却每次重建

**① 问题描述**
现状：`remove()`/`collapse()` 的注释写着「保留已加载的网页小地图，下次展开直接复用」，但 `addPanel()` 每次都重新建 `buildMapBox()` 与新网页视图。用户影响：维护者会误以为资源已受控而不再处理释放，与 H01 同源。触发条件：读/改这段代码时。
（证据：`NearbyPanelController.java:373-378` 注释；`:415-437` 实际每次重建。）

**② 优化方案**
按 H01 选定的方案同步注释：选复用就把 `buildMapBox` 改成「已存在就挂回」，选销毁重建就把注释改成「每次展开重新加载」。

**③ 优化后表现**
解决：注释与行为一致。
验收：通读 `remove/collapse/addPanel` 三处注释，与实现逐一对应。

## R8a1-L02 · 低风险 · 脚注位置写死 20dp，没有引用规格常量

**① 问题描述**
现状：底注定位用 `panelHeight - 20`，而 20 正是面板规格里的「有脚注时留白」常量，其它尺寸（命中区、地图、行高）都走了常量，只有这里写死。用户影响：以后调底注留白时面板总高会变、底注不动，文字会压边。触发条件：修改脚注留白常量时必然触发。
（证据：`NearbyPanelController.java:753-754`；常量 `NearbyOverlayModel.java:51` `FOOT_ROW_GAP`。）

**② 优化方案**
把 20 换成 `NearbyOverlayModel.FOOT_ROW_GAP`，与同文件其它尺寸引用方式一致。

**③ 优化后表现**
解决：底注与面板高度永远同步。
验收：改常量后重新展开面板，底注仍在卡片底边留白内。

## R8a1-L03 · 低风险 · 新建地图视图后「已就绪」标记还是上一份的

**① 问题描述**
现状：`createMapView()` 新建实例后没有把 `mapReady` 置回 false，只有「渲染进程回收」和「完全销毁」两条路径会重置。用户影响：收起后再展开时，首帧地图数据会被推给还没加载完的新页面并静默丢弃，靠页面加载完成回调再补一次，表现为地图慢半拍。触发条件：收起后再次展开。
（证据：`NearbyPanelController.java:551-616` 未重置；`:628`、`:642` 是仅有的重置点；`:976` 依赖 `mapReady`。）

**② 优化方案**
把 `mapReady = false` 放进 `createMapView()` 新建实例处（与销毁处成对），让「就绪」只描述当前这个视图。

**③ 优化后表现**
解决：就绪状态与视图实例严格对应，不再有「假就绪」。
验收：RocoPerf 里不再出现「推送成功但地图未更新」的首帧计数。

## R8a1-L04 · 低风险 · 冷启动在主线程读地图标定表

**① 问题描述**
现状：控制器构造里同步读 `assets/maps/maps.json`，而构造发生在主 Activity 创建阶段。用户影响：文件很小，正常无感；但严格模式下属于主线程 IO，标定表增大后会拖慢冷启动。触发条件：每次冷启动 / 进程重启。
（证据：`NearbyPanelController.java:183-184`、`:1200-1210`；构造调用点 `BattleOverlayController.java:163`。）

**② 优化方案**
首次展开面板时在后台线程读取并缓存，或直接复用网页侧同一份标定表注入；读取失败时仍退回雷达。

**③ 优化后表现**
解决：冷启动不再在 UI 线程做文件读取。
验收：StrictMode 开启后冷启动无 `DiskReadViolation`，首次展开仍能显示底图。

## R8a1-U01 · 不确定 · 用户拖动过的面板位置，下次展开是否应该保持？

**① 问题描述**
现状：拖动松手会把坐标写进面板偏好，但下次展开时只要拿到了球坐标就优先「贴球另一侧」，存档位置只在完全没有球坐标时才读；而字段注释写的是「下次展开沿用」。
用户影响：取决于产品口径——若要求「拖过就记住」，现在等于没记住；若按 2026-11-10 的「面板固定贴球」设计，则是注释过期。
置信度：中。**需要产品/原作者确认**：面板位置跟球，还是跟随用户上次拖动。
（证据：`NearbyPanelController.java:283-313`、`:352-362`、`:76-79`。）

**② 优化方案**
若「跟随拖动」：展开时优先用存档位置，仅当存档为空才贴球；若「跟着球」：删掉存档写入与读取，并把注释改成实际行为。

**③ 优化后表现**
解决：行为与文案统一，用户不会觉得「拖了白拖」。
验收：拖动面板到屏幕中部、收起、再展开，位置符合确认后的口径。
