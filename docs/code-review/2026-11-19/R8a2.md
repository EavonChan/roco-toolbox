## R8a2-H01 · 高风险 · 列表已经把命中的精灵全部列完，底部仍提示「还有 N 只未显示」，往下滑什么也没有

**① 问题描述**
现状：面板只把「命中筛选口径」的精灵放进列表，但底部「还有 N 只未显示」和「脚注是否显示」用的是附近精灵总数减去已显示行数，网页专门为列表口径给出的 `matched`（命中总数）字段在壳侧完全没有被读取。
用户影响：附近有 30 只、命中 3 只时，列表 3 行全部列出，脚注却写「还有 27 只未显示」，用户往下滑发现没有任何内容，会误以为面板坏了；同时脚注多占一行高度，面板整体被撑高。
触发条件：附近存在未命中筛选的普通精灵（游戏中很常见）。
（证据：`NearbyOverlayModel.java:155-156` 只取 `total`、`:227-229` `hiddenCount() = total - shownRows()`、`:239-241` 文案；`NearbyPanelController.java:693`、`:749-755` 据此决定脚注；网页口径 `src/nearby/overlayPayload.ts:99-100`「列表与『还有 N 只』都按 matched 算」、`:277-278` `total` 是全部附近精灵、`matched` 是命中数。）

**② 优化方案**
模型新增 `matched` 字段（缺省回退 `total`，兼容旧网页），`hiddenCount()` 改为 `max(0, matched - shownRows())`；标题里的「附近 N · 稀有 M」仍用 `total` / `rareTotal`。同步补一条测试：`total=30, matched=3, pets=3` 时应无脚注。注意 `NearbyOverlayModelTest.java:86-95` 现在的断言是拿 `total` 当列表总数写的，修口径时必须一起改，不能只改实现。

**③ 优化后表现**
解决：脚注只统计「命中但没显示完」的精灵，列表列完就不再出现「还有 N 只」。
验收：真机制造「附近 30 只、命中 3 只」的场景，面板 3 行铺满后不出现脚注；命中 30 只时出现「还有 6 只未显示」，滑动可看到剩余行。

## R8a2-L01 · 低风险 · 三个公开方法只有测试在调用，生产代码完全没用

**① 问题描述**
现状：`orbCountText()`、`parseMapScenes()`、`metaTextLine1()` 在主代码零调用，只有单测在断言它们，容易让后来的人以为「场景是否在标定表里」仍影响地图显隐。用户影响：无直接现象，但维护时会被误导。触发条件：无。
（证据：全局检索仅命中 `NearbyOverlayModelTest.java:219/301/309/344-345` 与声明处 `NearbyOverlayModel.java:231/276/385`；地图显隐实际只看 `NearbyPanelController.java:959-967`。）

**② 优化方案**
`metaTextLine1` 可保留并注明「旧口径兼容」，`orbCountText`、`parseMapScenes` 连同测试一起删掉，或加 `@Deprecated` 并写清「生产不再使用」。

**③ 优化后表现**
解决：不再有「看起来在用、实际没用」的口径入口。
验收：全局检索这三个名字，只出现在测试或带弃用标注的声明处。

## R8a2-L02 · 低风险 · 坐标字段只挡 NaN 不挡无穷大，坏数据会静默丢掉整帧地图

**① 问题描述**
现状：模型读数值时只用 `Double.isNaN` 判空，`±Infinity` 会被当成有效坐标；随后壳把坐标写进 JSON 时会被拒绝并整帧丢弃，地图停在上一帧且没有提示。用户影响：仅在收到非标准 JSON（手写 `Infinity`）时出现；标准 `JSON.stringify` 会把无穷大变成 `null`，当前网页链路不可达，属加固项。触发条件：上游序列化实现变化或旧客户端手拼 JSON。
（证据：`NearbyOverlayModel.java:195-199`；`NearbyPanelController.java:977-1011` 整段 try/catch 静默。）

**② 优化方案**
`numberOrNull` 改成 `Double.isFinite` 校验；`pushMapData` 的 catch 至少记一条 RocoPerf 日志，便于真机区分「没推」与「推了但被丢」。

**③ 优化后表现**
解决：异常坐标在解析层就被当成缺失，不会污染整帧。
验收：用 `{"self":{"x":"Infinity","y":1}}` 构造 payload，面板地图退回雷达而不是保持上一帧。

## R8a2-L03 · 低风险 · 稀有/可提醒总数直接信网页，可能与总数对不上

**① 问题描述**
现状：`rareTotal`、`alertTotal` 有就用网页给的数，不与 `total` 做任何夹取；网页字段异常时会显示「附近 5 · 稀有 9」这种自相矛盾的标题。用户影响：仅坏数据时出现。触发条件：网页统计口径变更或字段错位。
（证据：`NearbyOverlayModel.java:157-158`。）

**② 优化方案**
解析时夹到 `[0, total]`，并在超界时以列表实际计数兜底。

**③ 优化后表现**
解决：标题数字永远自洽。
验收：构造 `total=5, rareTotal=9` 的 payload，标题显示 `稀有 5`。

**③ 优化后表现**
解决：落点只有一套描述、一套实现。

## R8a2-L05 · 低风险 · 标定表整体缺失时，地图区是一块深色空矩形，没有雷达也没有提示

**① 问题描述**
现状：地图区只要「有自身坐标」就显示，但地图页只有在拿到标定表时才会画雷达/底图；标定表读不到时页面反复清空自身，只剩点击区底色。用户影响：打包漏文件或读取异常时，用户看到深色空块，会以为数据坏了。触发条件：`assets/maps/maps.json` 缺失/损坏。
（证据：`NearbyPanelController.java:603-607` 仅在 `catalogJson != null` 时注入；`assets/overlay-map.html:317-318`、`:333` 无标定即清空；`NearbyPanelController.java:963-967` 的 `hasMap` 不检查标定是否就绪。）

**② 优化方案**
地图页在无标定表时也画雷达骨架并显示「未找到地图标定」；或壳侧在标定缺失时收起地图区，让列表占满。

**③ 优化后表现**
解决：标定缺失时用户看到明确兜底，而不是空块。
验收：临时改名 `maps.json` 后展开面板，地图区出现雷达/提示。

## 复核结论（本次检查后未发现问题的点）

- **坐标换算口径一致**：几何函数全整数、单位统一 px，调用方先把 dp 换算再传入；`y` 轴在 `maps.json`（`"y":"south"`）、地图页投影与精灵点排布三处都是「y 越大越靠下」，箭头按朝向顺时针旋转，未见南北镜像（`OverlayGeometry.java:22-46`、`overlay-map.html:166-190/263-284/357-360`）。
- **夹紧与越界兜底**：屏幕比面板小时 `clamp` 退化为贴左/贴边，不会产生负数或 NaN；标定表参数非法时 `projectArt` 返回 null，地图页退回雷达（`OverlayGeometry.java:26-31`、`overlay-map.html:172-183`）。
- **测试未放水**：`OverlayGeometryTest` 覆盖四角/中心/横屏与「面板不压球」，断言与实现一致；`NearbyOverlayModelTest` 覆盖缺字段、显式 null、旧网页无 `mapPets`、面板开关兜底，未见「改松断言迁就实现」。唯一与实现绑死的是 `NearbyOverlayModelTest.java:86-95` 的脚注口径，属 H01 需要同步修改的断言。
- **面板开关兜底**：`panels` 缺失、非布尔、两项都关时一律回到两项都开（`NearbyOverlayModel.java:166-187`），与网页「开关变化立即重推」的用法一致。
