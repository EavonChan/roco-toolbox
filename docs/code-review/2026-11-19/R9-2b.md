## R9-2b-M01 · 中风险 · 开着悬浮窗蹲需求时，需求中心命中会停在应用启动那一刻，已完成或新发布的需求不再更新，面板与附近页可能给出不同结论

① 问题描述：现状是应用级推送 hook 只挂载时拉一次需求中心，之后不再刷新——`useDemandCenter` 本身没有轮询，60 秒缓存只解决「跨实例重复请求」，不负责过期重拉，`reload()` 也没有被推送 hook 调用；用户影响是长时间采集时，已被人接走/完成的需求仍把精灵标成「需求」排在最前，新发布的需求则完全不进面板；触发条件是保持应用进程不重启、连续采集超过数分钟。
（`src/nearby/useNearbyOverlayPush.ts:47` `useDemandCenter(supported)` 未使用返回的 `reload`；`src/ui/useDemandCenter.ts:56-72` 仅在 `accountId/nonce/enabled` 变化时请求，命中缓存即返回；对比 `src/ui/Nearby.tsx:192` 每次进入附近页重新挂载才刷新）

② 优化方案：推荐 A——推送 hook 在采集进行中每 60s 调一次 `reload()`，并在 `visibilitychange` 回到前台时补一次；B——把需求中心抽成应用级共享 store，附近页与推送共用同一份并按 TTL 刷新。推荐 A（改动约 10 行，不动接口）；风险是采集中每 60s 多一次小组需求请求（按小组数并发），弱网下失败沿用旧列表，需保证失败不清空。

③ 优化后表现：解决「面板需求命中过期」。验收：`npx vitest run src/nearby`（补一条用例：采集态下推进 60s 断言 `useDemandCenter` 被重新调用一次）；真机在附近页发布/接单一条需求后，不重启应用，1 分钟内悬浮窗命中随之更新。
