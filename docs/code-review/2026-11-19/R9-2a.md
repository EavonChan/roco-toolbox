## R9-2a-M01 · 中风险 · 切到「稀有 / 需求 / 蹲守」后，悬浮窗底部「还有 N 只未显示」和悬浮球数字把被筛掉的普通精灵也算进去，用户会以为漏看了一大批目标

① 问题描述：现状是 payload 同时给了「附近总数 `total`」与「筛选后命中数 `matched`」，但壳端算「还有 N 只未显示」与悬浮球数字时只读 `total`，`matched` 从未被使用；用户影响是范围切到稀有/需求/蹲守后列表只剩 1~2 行，底部却提示「还有 30 只未显示」、球上数字也显示 30，误以为目标没画出来；触发条件是附近页或悬浮窗把范围选为 `rare` / `demand` / `target`，且视野内有普通精灵。
（`src/nearby/overlayPayload.ts:99-100` 注释承诺「列表与『还有 N 只』都按 matched 算」、`:277-278` 输出 `total: pets.length` 与 `matched: items.length`；壳端 `android-shell/app/src/main/java/com/localdatatool/toolbox/capture/NearbyOverlayModel.java:155-156` 只取 `total`、`:227-229` `hiddenCount = total - shownRows()`、`:231-233` `orbCountText = total`；全仓 `git grep '"matched"' -- android-shell` 无匹配）

② 优化方案：推荐 A——只改壳端：`hiddenCount()` 与 `orbCountText()` 改读 payload `matched`（缺失时回退 `total`，兼容旧网页），标题「附近 N」继续用 `total` 表达视野总量；B——网页端把 `total` 改成命中数、另发 `nearbyTotal`，但会让旧壳的标题/球数字一起变，且需要网页先发版。代价：A 只动 `NearbyOverlayModel` 约 10 行并补一条 `matched` 用例，但必须重新构建 APK 才生效；两者都要保留「旧网页没有 matched 时行为不变」。

③ 优化后表现：解决「筛掉后仍提示还有一大堆」。验收：`cd android-shell; ./gradlew test`（`NearbyOverlayModelTest` 增加「total=30、pets=2、matched=2 → hiddenCount=0、orbCountText=2」用例）；真机切「稀有」档后底部文案与实际未展示行数一致。
