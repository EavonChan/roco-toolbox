## R9-4a-M01 · 中风险 · 桌面版从附近页切到别的页后，置顶小窗停在最后一帧不再更新，在别的页停止采集也不会收起

① 问题描述：现状是桌面小窗的推送逻辑仍挂在附近页组件里，离开页面即卸载、清理函数只清定时器不收起小窗，且 `useNearbySnapshot` 也随页面卸载停止轮询；用户影响是切到「我的/收集」后小窗一直显示离开前的精灵，采集中断了也看不出来，要回附近页才恢复或收起；触发条件是桌面版采集过程中离开附近页。
（`src/ui/Nearby.tsx:517-583`（推送 effect）、`:585-588`（卸载只 `clearTimeout`）、`:590-591` 注释说明手机端已迁到应用级；对比 `src/App.tsx:70` `useNearbyOverlayPush`；桌面桥在 `src/collector/desktopOverlay.ts`）

② 优化方案：推荐 A——把桌面推送也移到应用级（与 `useNearbyOverlayPush` 合并成一个 hook 内的两个通道分支），页面只负责开关与外观；B——最小改动：页面卸载时若正在采集则 `hideNearbyOverlay()`，并在 App 层恢复（但切回页面才重新出现）。推荐 A（一次修好，与安卓面板行为一致）；代价是需要把 `overlayVisible/clickThrough` 的状态上提，改动约 60~80 行。

③ 优化后表现：解决「切页后小窗停更/停不下来」。验收：桌面版开始采集→切到「我的」→小窗继续更新；在「我的」停止采集→小窗自动收起（可用 `npx vitest run src/ui/Nearby.test.tsx` 保证页面用例不回归）。

## R9-4a-M02 · 中风险 · 地图图例把玫瑰环标成「需求命中」，但玫瑰环其实是「可提醒」，真正命中需求的精灵在地图上没有任何标记

① 问题描述：现状是地图只认识 `alertReason`（体重牌+声音牌、±100dB 等可提醒条件），并用玫瑰环画出来，图例写的是「需求命中」；附近列表里「需求命中」用的是琥珀环，两处口径不一致；用户影响是在地图上看到玫瑰环会以为是需求精灵，实际只是可提醒，而真正的需求命中在地图上完全看不出来，蹲需求时容易跑错；触发条件是任意有可提醒精灵或需求命中的场景。
（`src/ui/NearbyMap.tsx:332-334`（玫瑰环 = `alertReason`）、`:373`（图例文案「需求命中」）；`src/ui/Nearby.tsx:507-513`（`mapPets` 只带 `alertReason/rare/kinds`，没有需求信息）；列表侧 `Nearby.tsx:884-930`（需求命中用琥珀环））

② 优化方案：A——图例改成「可提醒」，并把附近页的 `hitByKey` 里是否有命中传进地图，用与列表一致的琥珀环标需求命中；B——只改图例文案（一行），地图暂不区分需求。推荐 A（两个视图口径统一，改动约 20 行，`NearbyMap` 增加可选 `demandKeys`）；代价是地图点位多一次 `Set.has` 判断，可忽略。

③ 优化后表现：解决「地图和列表对『需求』说法不一致」。验收：`npx vitest run src/ui/NearbyMap.test.ts`，补「带需求命中时渲染琥珀环、图例写需求命中；仅 alert 时渲染玫瑰环、图例写可提醒」用例。

## R9-4a-L02 · 低风险 · 错误边界的「重新载入附近页」只清错误状态，同一条坏数据会立刻再次报错，按钮可能按了没效果

① 问题描述：现状是重试只是 `setState({error:null})`，子树用同一份模块状态快照重挂；用户影响是若异常来自某个字段组合（而非一次性渲染竞态），点按钮会立刻回到同一个兜底页，用户以为按钮坏了；触发条件是数据驱动的渲染异常。
（`src/ui/NearbyErrorBoundary.tsx:39-42`、`:80-83`；数据源 `src/collector/nearbyStore.ts` 模块级快照，重挂时不会变）

② 优化方案：重试时同时让数据层丢弃/刷新当前快照（例如调用 `refreshNearbySnapshot()`），或在 `componentDidCatch` 里记录错误签名，连续两次相同错误时提示「请停止采集后重进」。约 10 行；风险很低。

③ 优化后表现：兜底按钮有确定的恢复动作；验收：`npx vitest run src/ui/Nearby.test.tsx`，补「相同错误连续两次 → 显示第二段提示」。
