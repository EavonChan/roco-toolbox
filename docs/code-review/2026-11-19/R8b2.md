## R8b2-M01 · 中风险 · 包里已经是 42，对外清单还停在 40；直接出正式包会被构建拦下，绕过参数出包则用户收不到更新

**① 问题描述**
现状：构建脚本的版本号已升到 42/1.5.6，但正式站客户端实际读取的两份清单仍是 40/1.5.6；构建期一致性校验只在带内测参数时放宽为「包版本必须高于清单」，不带参数会直接失败。
用户影响：发版当天若直接执行正式构建会卡在校验；若为了出包加了内测参数，产物 versionCode 42 与对外清单 40 不一致，等于发出一份「客户端永远检测不到」的正式包。
触发条件：2026-11-19 发版窗口内构建正式包。
（证据：`build.gradle:35-37`、`:109-130`、`:261`；`public/android/version.json` 与 `version-18.json` 的 `versionCode` 均为 40；规范依据 `AGENTS.md`「包、清单、网页必须同一次发布窗内按『版本化包 → latest.apk → 两份主站清单 → 网页』做完」。）

**② 优化方案**
发版时把两份清单一起改成 42/1.5.6（或先把 `build.gradle` 回退到 40，发版时再统一升），保证 `verifyShellInvariants` 自然通过、不需要 `-PtestOnlyBuild`；构建前用 `node scripts/deploy-web.mjs` 前的版本自检脚本比对三处。

**③ 优化后表现**
解决：正式构建不需要放宽参数即可通过，产物版本与对外清单一致，更新提示可达。
验收：不带任何 `-P` 参数执行 `assembleRelease`，构建通过且打印 `version=1.5.6(42)`；线上两份清单同为 42。

## R8b2-M02 · 中风险 · 版本一致性校验只查旧清单，客户端真正读的那份漏改也能构建通过

**① 问题描述**

**② 优化方案**

## 复核结论（本次检查后未发现问题的点）

- **切服后的身份隔离**：WebView 的 WebStorage 按 origin 隔离，换站不清 WebStorage/Cookie、只清 HTTP 缓存与历史，切回原站身份仍在（`MainActivity.java:834-849`；`ServerConfig.java:83`）。
- **身份救援的边界**：仅正式通道且当前地址恰为正式站时运行；正式站已有令牌时直接标记完成、绝不覆盖；测试站也没有身份时静默跳过；失败/超时只影响本次，不阻塞启动（`IdentityRescue.java:46-57`、`:109-137`、`:88`）。
- **渲染进程回收重建**：先摘窗口再销毁旧 WebView，按标准序列摘 JS 接口、断页面、销毁，重新接线并重设渲染优先级；采集在 VpnService 内不中断（`MainActivity.java:551-566`、`:568-580`）。
- **onDestroy 清理**：定时任务、文件选择器、采集停止回调、采集器、更新器、悬浮窗、WebView 全部释放，无遗留强引用（`MainActivity.java:524-537`）。
- **文件选择器**：`onShowFileChooser` 前后都取消上一个回调，销毁时也取消，未发现悬挂回调（`MainActivity.java:317-340`、`:528`、`:591`）。
- **通知渠道**：前台采集通知使用独立低优先级渠道，Android 8 以下不建渠道、Android 14 带 specialUse 类型启动前台服务（`CaptureVpnService.java:22-23`、`:36-47`、`:164`）。
- **清单安全项**：`allowBackup=false`、`fullBackupContent=false`、数据提取规则、明文流量关闭、Provider 不导出且 authority 用 `${applicationId}`（`AndroidManifest.xml:15-28`、`:76-84`）。
- **通道隔离**：applicationId、默认站、清单地址、应用名按通道注入，生成 BuildConfig 后再次断言，正式 bundle 不允许出现测试站/内测清单（`build.gradle:16-17`、`:29`、`:197-202`、`:217-261`）。
- **签名与产物**：keystore 与 `*.jks` 未入库，APK 不进版本库（`.gitignore:1-10`）；`configChanges` 覆盖旋转/密度变化，旋转不会重建 WebView（`AndroidManifest.xml:32`）。
- **分享入口**：`singleTask` 下 `onNewIntent` 重新处理分享，未丢失新 Intent（`MainActivity.java:620-623`、`:634`）。

## IdentityRescue.java:37 救援超时是否要按步骤放宽
