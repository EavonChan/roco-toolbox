## 三、问题

### R3b2-L01 · 低风险 · 小组页组件对外还挂着二十多个「传了也没用」的参数

**① 问题描述**
- **现状**：`GroupPlanHub` 的类型声明仍继承整个 `MotherGroupResourcesProps`，而实现只读 `group / viewerAccountId / species / snapshots` 四项。
- **用户影响**：当前没有可见异常；但以后任何人给这一层补参数（例如想通过 `snapshots` 之外的数据影响展示）都会发现「传进去没反应」，排查成本落在接手上。
- **触发条件**：`CollectionGroups` 挂载时按旧契约传 28 个 props（`CollectionGroups.tsx:394-424`），其中 `catalogVersion / criteriaId / target / recommendations / targetMode / natureOverrides / studGroupCount / tasks / tasksConfirmed / tasksPendingMemberIds / tasksLoading / tasksError / isOwner / onClaimTask / onReleaseTask / onTransferTask / demands / completedCounts / myRecentCompleted / onPublishDemand / onWithdrawDemand / onClaimDemand / onReleaseDemand / onCompleteDemand` 共 24 项被丢弃（类型契约见 `src/ui/MotherGroupResources.tsx:147-200`，实现见 `src/ui/plan/GroupPlanHub.tsx:3-6`）。

**② 优化方案**
把 `GroupPlanHubProps` 收成只含 `EggMatchingHub` 真正需要的 6 项（`group` 或 `groupId / viewerAccountId / species / members / snapshots` + `className`），并让 `CollectionGroups` 同步只传这几项。这样编译器会立刻点出「这 24 个 props 已经没人消费」——它们中真正还有用的（如 `demands` 给成员区）已经在 `CollectionGroups` 内部另有用处，不受影响。改动约 30 行，风险低；与 R3b3-H01 的需求中心下线一并处理更合适。

**③ 优化后表现**
- **解决**：调用方一眼看清这一层需要什么，不再出现「传了也不生效」的契约。
- **验收**：`npx tsc -b` 通过；`src/ui/CollectionGroups.tsx` 的 `<GroupPlanHub` 只剩 6 个属性行。
