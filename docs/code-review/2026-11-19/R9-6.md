## R9-6-H01 · 高风险 · `npm run deploy:prod` 仍直接 `wrangler pages deploy --branch=main`，完全绕过新发版脚本的批准与断言，2026-11-10 的事故路径依旧可用

① 问题描述：现状是发了 `scripts/deploy-web.mjs` 作为唯一发版入口（强制 `--branch`、main 必须 `--approve-production`、bundle 必须含 `RocoServer` 且不得含「收集计划」、正式清单 apkUrl 必须是正式包），但 `package.json` 里的 `deploy:prod` 仍然是 `npm run verify && npm run build && wrangler pages deploy ... --branch=main`；用户影响是任何人（包括自动化/肌肉记忆）执行一次 `npm run deploy:prod` 就会把当前工作区直接顶到正式站，且没有任何断言，正是 2026-11-10 连续三次误发 main 的同一路径；触发条件是执行该 npm script。
（`package.json:23-24`；`scripts/deploy-web.mjs:45-51`（门禁）、`:67-73`（文案断言）、`:75-129`（清单断言）；AGENTS.md「发版只走 scripts/deploy-web.mjs，不要手敲 wrangler pages deploy」「`npm run deploy:prod` 默认会拒绝执行」）

② 优化方案：把两个 script 改成调用脚本：`deploy:test` → `node scripts/deploy-web.mjs --branch test`；`deploy:prod` → `node scripts/deploy-web.mjs --branch main`（不带 `--approve-production`，即默认中止，放量时手动补）；`wrangler pages deploy` 只保留在脚本内部。约 2 行 + 在 README/AGENTS 标注 `-- --approve-production` 用法；风险为零（脚本行为已由 2 条测试覆盖）。

③ 优化后表现：解决「一条命令绕过全部护栏」。验收：`npm run deploy:prod` 必须打印 `[发版中止]` 且退出码非 0；`node --test tools/test/deploy-web.test.mjs` 保持通过。
