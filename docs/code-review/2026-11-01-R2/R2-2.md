## 1. 问题清单

### R2-2-H01 撤回重发的单会继承旧的「已上窝」勾选（已修 `e5d842b`）

- **① 现状**：勾选键尾原用需求版本号，注释声称能区分重发；但服务端撤回是整行删除、重发后版本号从 0 重计，键和旧勾选完全一样。**用户影响**：重新接单后新单一来就打着旧勾，用户可能漏上窝。**触发**：需求方撤回→重发同内容→你再次接单，每次都复现。（`demandPlacementStore.ts:27-36` 键含 `claimedAt`；服务端 publish 为 `version=0`、claim 为 `version+1`）
- **② 方案**：键尾换成每次接单刷新的接单时间；旧键自然作废、无需迁移。
- **③ 验收**：`HomeDemandPlacements.test.tsx`「撤回重发不继承勾选」用例通过。

### R2-2-H02 换成另一组候选配对后，页头窝数与实际要放的精灵对不上（已修 `f76d3e3`）

- **① 现状**：切换候选只改这一行显示哪一对，整份方案仍按第一组算，「已用 N/窝」不跟着变，候选里的亲本可能已被后面单占满。**用户影响**：照页面抄作业会少一个窝，或让同一只精灵超过「最多服务 2 条」的上限。**触发**：某条单有 2 组以上候选且用户切到非第一组。（`HomeDemandPlacements.tsx:235-236` 的 `active` 原取 `options[optionIndex]`；`demandPlacement.ts` 候选在分配当时算好后只有 `best` 写进占用）
- **② 方案**（用户 2026-11-01 拍板选 A）：把用户挑的配对作为偏好传给分配入口，命中就排到第一并重算其余单；严格 1:1 轮没给到偏好时再看 1:2 轮，排不上才回落默认并提示。代价：域层新增两个可选字段，约 30~50 行。
- **③ 验收**：`domain/demandPlacement.test.ts` 22 用例、`HomeDemandPlacements.test.tsx`「换候选后概率跟着这一对变」均通过。

### R2-2-M01 切换云账号的瞬间，接单列表还显示旧账号的单（已修 `54e73ad`）

- **① 现状**：身份变化时只在缓存命中新身份才更新列表，不命中时旧列表原样留着。**用户影响**：换身份的几秒里看到上一个账号的单，此时勾「已上窝」会写进新账号的键。**触发**：组件保持挂载时发生账号切换（现流程很小，属埋雷）。（`useClaimedDemands.ts:64-66`）
- **② 方案**：effect 开头统一 `setItems(缓存命中 ? 缓存 : 空)`。
- **③ 验收**：`useClaimedDemands.test.tsx`「换身份后旧响应不回写」通过。

### R2-2-M02 三个本机记忆写存储没兜底，隐私模式点一下直接抛错（已修 `9b8a9d2`）

- **① 现状**：勾选、收起、结单「知道了」、家园分页切换四处 `setItem` 没有 try/catch。**用户影响**：存储不可写时点一下就抛未捕获异常，事件中断。**触发**：隐私模式 / 配额满。（同模块 `demandPickStore.ts:31-38`、`lastTab.ts` 都有兜底）
- **② 方案**：四处包 try/catch，失败只影响「下次记不住」，本次界面照常更新。
- **③ 验收**：相关组件测试通过；`tsc -b` exit=0。

### R2-2-M04 回来再看时，勾过「已上窝」的那条单换了一组配对（已修 `260f6e8`）

- **① 现状**：选的候选只存页面内 state，切走再回来默认回到第 1 组，勾选却还留着。**用户影响**：看到一对自己没放进去的精灵被标成已上窝，回头配窝会配错。**触发**：有 ≥2 组候选且选过非第一组，每次重进必现。（`HomeDemandPlacements.tsx` 原 `selectedOptions`；勾选键不含「第几组」）
- **② 方案**：新增 `roco.demandPlacementChoice:<云身份>`，按行键记母本/种公个体号（不是序号），重进读出作为方案偏好；坏值当没挑过。
- **③ 验收**：`HomeDemandPlacements.test.tsx`「重进仍按那一对显示」、`demandPlacementStore.test.ts` 读写/坏数据用例通过。

### R2-2-M06 有一个小组读失败时，页面只多一行黄字，不给重试（已修 `a2f90cd`）

- **① 现状**：只有全部组失败才出现带重试的错误块，部分失败降级成一行纯文本。**用户影响**：弱网或某组被解散时少掉的单补不回来，只能退出重进。**触发**：任一组抛错且至少一组成功。（`HomeDemandPlacements.tsx` 原 `error && items.length === 0` 分支）
- **② 方案**：两处错误态收进同一 `renderError`，部分失败保留已读到的单并在上方给「重试」。
- **③ 验收**：`home-demand-retry` 用例（部分失败仍给重试）通过。

### R2-2-M08 每次切回家园页，都要把每个小组的需求重新拉一遍（已修 `8a0f77b`）

- **① 现状**：进页面先拉组列表，再对每组各发一次请求；缓存只用来「先显示旧内容」，不判断新鲜度，请求也不可取消。**用户影响**：弱网下切回上窝页要等 1+N 个请求；页面切走后请求还在跑。**触发**：每次进入家园页。（`useClaimedDemands.ts:70-78`，N+1；`loadedAt` 写了没人读；接口支持 `AbortSignal` 但没传）
- **② 方案**：60 秒内缓存直接复用（重试强制刷新），两个接口接 `AbortController`，中止不当成失败。
- **③ 验收**：`useClaimedDemands.test.tsx`「60 秒内不重拉 / 重试强制刷新」「部分失败合并」通过。

### R2-2-M09 这套请求与几个本机记忆原先完全没有测试（已修 `2f5e1af`）
