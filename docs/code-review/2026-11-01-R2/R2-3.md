### R2-3-M02 撤回需求的本地回写没有切组守卫，慢网切组后会误删新组同条件需求、并污染旧组缓存（复核 B6-M04：仍未修）

- **问题描述**：现状是撤回动作在请求返回后直接把「当前列表按条件过滤」写回状态与缓存，全程不校验
  组 / epoch 是否已切换；B6-M04 移交后 HEAD 里仍未修。用户影响：点撤回后立刻切组，旧组响应到达时会把
  新组列表里同条件的需求误删（下次轮询才恢复），同时旧组的本地缓存被写成新组的过滤结果。
  触发条件：撤回请求在途时切组或切身份。（证据：useCollectionGroups.ts:441-467 `withdrawDemand`
  无 `active()` 判断、缓存键用请求前捕获的 groupId；对照同文件 :406-408 mergeDemand 有组守卫、
  :334-349 loadTasks 有 epoch+序号双重守卫）
- **优化方案**：`await withdrawDemandApi(...)` 前取 `const active = scope(true)`，返回后先
  `if (!active()) return;` 再做 applyDemands（scope 已覆盖切组与切身份，selectGroup / subscribeSession
  都会抬 epoch）。**修复点在被占文件 useCollectionGroups.ts，本批不动，记为「暂缓移交」（B6 起第三批移交）。**
  代价：3 行，无行为变化。
- **优化后表现**：切组 / 切身份后旧撤回响应直接丢弃，新组列表与两组缓存都不被污染。
  验收（移交后执行）：hook 级用例「撤回在途切组，旧响应不写回」（B6-M05 要求补 hook 测试时一并覆盖）。

### R2-3-M03 接单 / 放弃 / 结单失败后不刷新需求列表，要等大版本轮询才恢复真实状态

- **问题描述**：现状是需求动作失败只把错误抛给界面，本地列表保持旧状态最长 60 秒；而同文件的
  认领 / 释放 / 转交任务在失败时会立刻重拉任务列表校准，两类动作两套口径。用户影响：版本冲突
  （别人同时接单 / 需求方已撤回）时，卡片还显示「待承接」，再点再失败，用户以为系统坏了。
  触发条件：多人同时操作同一条需求导致版本冲突。（证据：useCollectionGroups.ts:469-494 `demandAction`
  catch 直接 throw；对照 :1016-1022 claimTask 失败时 `void loadTasks(groupId)`；
  依据：同模块既有写法「竞争失败时立即拉一次当前状态，而不是等轮询」:1019 注释）
- **优化方案**：`demandAction` 的 catch 里补 `void loadDemands(groupId)` 再 rethrow（与 claimTask 对齐，
  groupId 为请求前捕获值，loadDemands 内部有 epoch+序号守卫，切组后不会误写）。
  **修复点在被占文件 useCollectionGroups.ts，记为「暂缓移交」。** 代价：2 行。
- **优化后表现**：冲突失败后列表立即刷新成真实状态，错误提示与界面一致。
  验收（移交后执行）：hook 级用例「接单 409 后触发重新拉取」。

### R2-3-M04 换身份 / 自动回退切组时不重置轮询版本号，可能一直跳过新组详情拉取

- **问题描述**：现状是「上次比对到的服务器版本号」只在手动点组时清零；换身份、组被解散后自动落到
  另一个组这两条路径都不清。用户影响：若新旧两组的详情版本号恰好相同（小组版本号都很小，极易撞），
  轮询会一直认为「没变化」而跳过详情拉取，成员与资源变更要等该组下次有人改动才能看到。
  触发条件：切云账号后自动进组、或当前组 404 后自动落到另一组，且两组 detail 版本号相等。
  （证据：useCollectionGroups.ts:305 versionRef 只在 :781 selectGroup 清零；:499-533 subscribeSession
  与 :553-574 applyGroupList 切组时不清；:727-731 版本相等即跳过 loadDetail）
- **优化方案**：subscribeSession 与 applyGroupList 改 `groupRef.current` 的两处各补
  `versionRef.current = null;`（与 selectGroup:781 对齐）。
  **修复点在被占文件 useCollectionGroups.ts，记为「暂缓移交」。** 代价：2 行。
- **优化后表现**：任何路径切组后第一次轮询都会完整拉一次详情。
  验收（移交后执行）：hook 级用例「自动切组后首轮轮询拉详情」。
