### R2-3-H02 撤回请求还没回来就切组，会把新组的需求列表换成旧组的

- **① 问题描述**：现状是撤回在请求返回后直接用「当前列表按条件过滤」写回状态与本地缓存，全程不校验组 / 身份 / epoch；用户影响是慢网切组后，新组的列表会被旧组结果覆盖或误删同条件行，旧组的缓存还会被写成新组的数据，最长到下次刷新（60 秒）才恢复；触发条件是撤回请求在途时切组或换身份。证据：useCollectionGroups.ts:441-467 `withdrawDemand` 没有 `active()`，:313-317 `applyDemands` 无条件 `setDemands` 并按请求前捕获的 groupId 写缓存；对照 mergeDemand:406-408、loadTasks:334-349。
- **② 优化方案**：请求前取 `const active = scope(true)`，`await withdrawDemandApi(...)` 返回后先 `if (!active()) return;` 再做本地过滤与缓存写入（scope 覆盖切组与切身份，selectGroup / subscribeSession 都会抬 epoch）。代价 3 行，无行为变化。**说明**：上一轮记为中风险，本批按「串组显示 + 旧组缓存污染」重定为高，且已是 B6-M04 起第三次移交。
- **③ 优化后表现**：切组 / 换身份后旧的撤回响应直接丢弃，新组列表和两组缓存都不被污染。验收：hook 级用例「撤回在途切组，旧响应不写回、B 组列表与 A 组缓存不变」。
