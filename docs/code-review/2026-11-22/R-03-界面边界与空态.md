## R3-P1-01 · 宽横屏精灵背包点「四列」立刻弹回「五列」，且四列选择不落盘

- **严重度**：P1
- **位置**：
  - `src/ui/MyPets.tsx:400-405`（宽屏自动补五列的副作用）
  - `src/ui/myPetsFilterStore.ts:157`（`persist()` 只在 `columns !== 4` 时才写盘）
  - `src/ui/myPetsFilterStore.ts:214-218`（`hasChosenColumns()` 只看模块加载时那份 `persisted`）
- **现状**：宽横屏（≥1120px 横屏）首次进入背包时若没选过列数，会自动把 4 列改成 5 列。判断"用户选过没有"用的 `hasChosenColumns()` 读的是**模块初始化时**解析出来的 `persisted` 对象；而"选四列"这件事因为等于默认值，`persist()` 根本不会写进 localStorage。
- **用户影响**：
  - 点「四列」→ 组件重渲染 → 副作用再次成立 → 立刻变回「五列」，**这个按钮在宽横屏上等于坏了**；
  - 就算把列数当默认值处理，用户从「三列」切到「四列」后刷新，localStorage 里仍是 `columns: 3`，回来又变三列 → 选择被静默吞掉。
- **触发条件**：横屏且 ≥1120px（平板横放 / 桌面窗口）100% 复现；竖屏不出现（竖屏只显示 3/4 两个按钮且不走这段副作用）。
- **证据**：

```tsx
// src/ui/MyPets.tsx:400-405
const wideLandscape = useWideLandscape();
useEffect(() => {
  if (wideLandscape && !hasChosenColumns() && columns === 4) setMyPetsColumns(5);
}, [wideLandscape, columns]);
const effectiveColumns = wideLandscape ? columns : (Math.min(columns, 4) as 3 | 4);
```

```ts
// src/ui/myPetsFilterStore.ts:157 —— 4 列永远不落盘
if (columns !== 4) value.columns = columns;
// :214-218 —— 判断依据是加载时快照，不是当前选择
export function hasChosenColumns(): boolean {
  return ([3, 4, 5, 6] as const).includes(persisted.columns as CardColumns);
}
```

- **建议修法**：把"用户是否显式选过"变成一个**内存标志**（`let columnsChosen = persisted.columns !== undefined`），`setMyPetsColumns` 里置 true，并且**任何一次显式选择都落盘**（含 4 列，删掉 `if (columns !== 4)` 的条件）；`hasChosenColumns()` 改读这个标志。副作用再补一条 `columnsChosen` 依赖，避免同一轮里又被改回去。
  - 代价：`myPetsFilterStore` 约 10 行 + 一条持久化用例，无 schema 变化（`columns` 允许 3–6，旧数据兼容）。
- **验收**：
  - `npx vitest run src/ui/myPetsFilterStore.test.ts src/ui/MyPets.test.tsx`
  - 新增用例：`localStorage` 写入 `columns: 4` → 重新 import 后 `getMyPetsColumns() === 4` 且 `hasChosenColumns() === true`
  - 手工：1280 宽横屏进背包 → 点「四列」→ 停住不变 → 刷新仍是四列。
- **归属**：**S4**（`MyPets.tsx`、`myPetsFilterStore.ts` 都在 S4 范围）。

## R3-P1-02 · 窄横屏看板：右栏固定 24rem，主区只剩 115–173px

- **严重度**：P1
- **位置**：
  - `src/index.css:67`（横屏根字号 `clamp(15px, 9px + 0.55vw, 21px)`）
  - `src/index.css:71`（左侧竖栏 `width: 6.2rem`）
  - `src/index.css:106`（`main…max-w-md` 左内边距 `7rem`）
  - `src/index.css:115`（看板 `grid-template-columns: minmax(0,1fr) minmax(0,24rem)`）
  - `src/ui/Dashboard.tsx:409`（右栏 `.dashboard-left`）、`:611-633`（主区）
- **现状**：横屏下看板是"左主区 1fr + 右信息栏固定 24rem"。手机横放（667×375、609×340 这类，代码注释里明确写了实测 609×340）根字号被夹到下限 15px，于是：竖栏 93px + 左内边距 105px + 间距 15px + 右栏 360px = 573px，**667 宽只剩约 173px 主区，609 宽只剩约 115px**。
- **用户影响**：手机横放打开看板，配窝建议/种公推荐被压成一列一百多像素的窄条，卡里文字挤成一团；用户得先找到「收起右栏」按钮才有正常版面。这一条和 2026-11-22 `db30374`（"窄横屏配窝卡改自适应列数，修掉卡片撑出容器"）是同一个根因的两面——**修掉的是溢出，没修"主区只有 86px"这件事**。
- **触发条件**：手机横放（屏宽 < 900px 且横屏）默认必现；点「收起右栏」后恢复。宽横屏（≥1120）正常。
- **证据**：

```css
/* src/index.css:67,71,106,115 */
html { font-size: clamp(15px, calc(9px + 0.55vw), 21px); }
div.sticky.top-0 { position: fixed; inset: 0 auto 0 0; width: 6.2rem; … }
main.mx-auto.max-w-md, div.mx-auto.max-w-md { … padding: 0 0.9rem 0.8rem 7rem; }
main[data-testid="dashboard-page"] { grid-template-columns: minmax(0, 1fr) minmax(0, 24rem); … }
```

```text
667×375（根字号 15px）：667 − 105(7rem) − 13.5(0.9rem) − 15(1rem gap) − 360(24rem) ≈ 173px
609×340（根字号 15px）：609 − 493.5 ≈ 115px
```

- **建议修法**：给窄横屏加一条断点，把右栏改成比例或默认收起，例如
  `@media (orientation: landscape) and (max-width: 900px) { main[data-testid="dashboard-page"] { grid-template-columns: minmax(0,1fr); } .dashboard-left { display: none; } }`
  并用 `useLandscape()` 把 `leftCollapsed` 的默认值在窄横屏下置 true（`Dashboard.tsx:70-73` 已有 `landscape && leftCollapsedState` 的写法，加一个宽度条件即可）。代价：窄横屏看不到账号/进度栏，需要点「显示右栏」；建议按 A/B 各截 375/390 与 667×375 图给 P 选。
- **验收**：手工在 667×375 与 609×340 两个视口各截一张看板图，主区配窝卡宽度 ≥ 屏幕宽度的 60%；`npx playwright test e2e/dashboard.spec.ts` 不回归。
- **归属**：S2（看板）+ S6（`index.css` 外壳横屏规则）。

## R3-P2-01 · 宽横屏「母本缺口」面板的空态文案取自「看板行动」开关，会出现"种公"字样

- **触发条件**：宽横屏（≥1120）且母本侧无内容（`visible.length === 0`、无 `motherGaps`）时必现；竖屏因为只显示一个面板不受影响。

- **验收**：`npx vitest run src/ui/Dashboard.test.tsx`，新增一条：宽横屏视口下母本栏空态不含"种公"字样。

## R3-P2-03 · 母本三列判定量的高度可能来自 `content-visibility` 的占位值（低置信，需实测）

- **严重度**：P2（置信度：中）
- **位置**：`src/ui/MotherView.tsx:479-521`（`useLayoutEffect` 里量 `getBoundingClientRect().height` 后调 `shouldUseThreeColumns`）、`:715`（每个蛋组容器带 `contentVisibility:'auto', containIntrinsicSize:'auto 180px'`）、`src/ui/motherColumnLayout.ts`
- **现状**：判定"两列一屏放不放得下"时，代码把容器临时改成 2 列再逐个子元素量高度。但子元素本身声明了 `content-visibility: auto` + `containIntrinsicSize: auto 180px`——**还没渲染过的离屏分组，量到的是 180px 的占位高度**，不是真实高度。
- **用户影响**：宽横屏收起筛选栏时，三列/两列可能按"假高度"决定，表现为"明明一屏放得下却排成三列"或反之；只影响 ≥1200px 横屏 + 收起筛选的组合。
- **触发条件**：宽横屏 + 收起右侧筛选 + 蛋组卡片超过一屏时；不同卡片高度差异越大越容易判断错。
- **证据**：

```tsx
// src/ui/MotherView.tsx:715（渲染处）
style={{ contentVisibility: 'auto', containIntrinsicSize: 'auto 180px' }}
// src/ui/MotherView.tsx:505-519（量高处）
.map((child) => child.getBoundingClientRect().height);   // ← :511
setThreeColumns(shouldUseThreeColumns({ sectionHeights: heights, … }));  // ← :518-519
```

- **建议修法**：量高时临时去掉 `content-visibility`（给列表加一个 `data-measuring` 属性，CSS 里 `[data-measuring="true"] > * { content-visibility: visible; }`），量完立即移除；或改用 `element.offsetHeight` 之前先 `getComputedStyle` 判断是否被跳过。也可以退一步：用 `containIntrinsicSize: 'auto'`（不写死 180px）让浏览器记住真实尺寸，第二次测量就准。
- **验收**：手工在 1280×800 横屏、收起筛选、蛋组 ≥8 个时确认"显示更多蛋组"按钮消失时布局为两列；`npx vitest run src/ui/motherColumnLayout.test.ts src/ui/MotherView.test.tsx`。
- **归属**：S2。

$ git diff a0f5a99 f952a93 -- e2e/my-pets.spec.ts | Select-String 'count\(\)'

- **建议修法**：在切到「未收集」后补一条**不依赖搜索**的断言：`await expect(page.getByTestId('mother-chain-group-list').first()).toBeVisible()` 且 `expect(await page.getByTestId('mother-chain-row').count()).toBeGreaterThan(10)`（若四列后首屏组数变少，就把阈值按当前 `INITIAL_CHAIN_SECTIONS=2 × 每组行数` 重算，别写死 10）。
