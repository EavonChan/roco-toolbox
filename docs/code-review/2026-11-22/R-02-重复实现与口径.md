## R2-P1-01 · 母本页奖牌：「显示的档」和「判定的档」是两份数据，默认显示大婉但判定按四档全算

- **严重度**：P1
- **位置**：
  - `src/ui/MotherCriteriaMedals.tsx:39-43`（显示取全局 `coverageFilter.grades`）
  - `src/ui/MotherCriteriaMedals.tsx:64-70`（点档位顺手写全局目标 `setTargetGrade`）
  - `src/ui/MotherCriteriaMedals.tsx:102-115`（把"体型×声音集合"折叠成第一个匹配档位）
  - `src/ui/MotherView.tsx:267`、`:329-341`（判定与背包跳转用 `motherCriteria`）
  - `src/ui/Dashboard.tsx:119-131`（看板注释明确写着「母本进度只认母本页自己的奖牌口径（上游 R7b-H01）」，正是为了防这种跨页联动）
- **现状**：
  ① 母本页把「全局目标档位」（看板/覆盖度那份）当成自己的选中态来画；
  ② 但「已收集 / 共 N 条链」的判定、以及点卡片「查看」带去背包的筛选，读的是另一份 `motherCriteria`；
  ③ `motherCriteria.grades` 缺失时（新装用户 / 从没点过奖牌的老数据），`selectedGradesFor` 会把 `bodies:['大块头','小不点'] × voices:['+100','-100']` 这套默认**折叠成第一个匹配档「大婉」**返回，于是界面显示「大婉已选」，判定实际是"四档都算"。
- **用户影响**：
  - 新装用户进「收集 · 母本」，看到「大婉」高亮，但顶部「已收集 N」是把大粗/小婉/小粗的母本也算进去的——数字比显示口径更宽松，用户对不上账；
  - 点同一张"已收集"卡片进精灵背包，`jumpBase` 又按「大婉」拼标签（`MotherView.tsx:341`），可能一只都搜不到 → 「已收集却搜不到」；
  - 在母本页换档位会**顺手改掉看板和覆盖度的种公目标档位**，种公缺口数、覆盖度分母随之变化（反向的跨页联动，正是 R7b-H01 要避免的那类）。
- **触发条件**：默认必现（新装/未设过档位）；在母本页点任一档位后，看板种公目标同步被改写也必现。
- **证据**：

## R2-P1-02 · 宽横屏看板左右两栏各挂一份配窝卡，窝数勾选互不同步、后写的覆盖先写的

- **严重度**：P1
- **位置**：
  - `src/ui/Dashboard.tsx:611-633`（宽横屏两栏，各自 `nestCard('studs')` / `nestCard('mothers')`）
  - `src/ui/NestPlanCard.tsx:31-38`（`NEST_PICKS_STORAGE_KEY = 'roco.nestPicks.v1'` + `readNestPicks`）
  - `src/ui/NestPlanCard.tsx:1248`（组件内 `useState(readNestPicks)`）、`:1252-1258`（每次变化整份回写 localStorage）
- **现状**：宽横屏（横屏且 ≥1120px）时看板同时挂两个 `NestPlanCard` 实例（左「种公推荐」、右「母本缺口」）。两个实例各自持有一份 `nestPicks` state，初始化时都从同一个 localStorage key 读，任何一次勾选都把**自己那份全量**写回同一个 key。
- **用户影响**：
  - 在左栏勾了某只精灵的窝，右栏同一只精灵的卡仍是未勾 → 两栏标题的「用 N 个窝」数字不一样，用户不知道哪个算；
  - 右栏再勾一次，会用"不含左栏新增"的那份整体覆盖 → 刷新后左栏的勾选凭空消失（用户手动标记的窝位丢失）。
- **触发条件**：横屏且屏宽 ≥1120px（平板横放、桌面窗口）必然触发；竖屏与手机横屏（<1120）只挂一个实例，不受影响。
- **证据**：

```tsx

<div className="dashboard-panels" data-testid="dashboard-main-column">
  <div className="dashboard-panel">…{owned.length > 0 ? nestCard('studs') : null}…</div>
  <div className="dashboard-panel">…{owned.length > 0 ? nestCard('mothers') : null}…</div>
```


- **建议修法**：把窝数勾选提升成模块级 store（照 `src/ui/createModuleStore.ts` 已有的写法，`suggestionCardStore` / `coverageFilterStore` 都是这个模式），两个实例共用一份并订阅同一次变更；不想动架构的话，最小改法是给 `NestPlanCard` 加 `picks` / `onPicksChange` 受控属性，由 `Dashboard` 持有唯一 state，两栏传同一份。
  - 代价：动 `NestPlanCard` 的 props（S2 名下文件）+ 一条新 store 用例，约 40 行；风险低（有 `NestPlanCard.test.tsx` 754 行用例兜底）。
- **验收**：`npx vitest run src/ui/NestPlanCard.test.tsx src/ui/Dashboard.test.tsx`；手工：横屏 1280 宽 → 左栏勾一窝 → 右栏同名账号标题的「用 N 个窝」同步 +1 → 刷新后仍为同一数字。
- **归属**：**S2**（`Dashboard.tsx`、`NestPlanCard.tsx`）、store 放 `src/ui/` 下同层。

## R2-P2-02 · 账号格列数用写死的 12px/6px/16px 估宽，横屏根字号被放大后判断偏乐观

- **严重度**：P2
- **位置**：
  - `src/ui/accountOrder.ts:59-84`（`isWide` 12px / 6.6px、`CHAR_GAP = 6`、`TAB_PADDING = 16`）
  - `src/ui/NestPlanCard.tsx:1598`（账号格 `text-xs` = 0.75rem）、`:1584`（`gap-1.5`）、`:1519-1522`（用 `accountTabColumns` 定列数）
  - `src/index.css:67`（横屏把根字号放大到 `clamp(15px, 9px + 0.55vw, 21px)`）
- **现状**：`accountTabColumns` 用固定 px 估算"这个名字要多宽"，其中汉字按 12px、左右内边距按 16px 算——这套数字只对根字号 16px 成立。但横屏时根字号被 `clamp(15px … 21px)` 改写，`text-xs` 实际是 11.25–15.75px，`px-2` 是 15–21px。
- **用户影响**：宽屏（根字号 > 16px）下会**高估**能放的列数，账号名（`whitespace-nowrap` 且没有 `truncate`/`overflow-hidden`，见 `NestPlanCard.tsx:1598`）会溢出格子、压到相邻账号；这正好违背该函数注释里承诺的"任何情况下都不换行、不截断账号名"。
- **触发条件**：横屏且屏宽足够让根字号 > 16px（约 ≥1273px 宽），配合 4 个以上账号 + 较长名字时可见。
- **证据**：

```ts
// src/ui/accountOrder.ts:59-84（节选）
const isWide = (char: string): boolean => /[\u1100-\u115f…]/.test(char);
const CHAR_GAP = 6;
const TAB_PADDING = 16;
const textWidthOf = (text: string): number =>
  [...text].reduce((sum, char) => sum + (isWide(char) ? 12 : 6.6), 0);
```

```css
/* src/index.css:67 —— 横屏把 rem 基准改了，上面那套 px 估算随即失效 */
html { font-size: clamp(15px, calc(9px + 0.55vw), 21px); }
```

- **建议修法**：不要再按字符估宽。账号格文字量很小（≤6 个格），直接量：对每个按钮渲染后 `getBoundingClientRect().width` 或 `scrollWidth > clientWidth` 检测，超过就降一列（`ResizeObserver` 已经在 `tabsRef` 上用了，`NestPlanCard.tsx:1427-1436`）。退一步的临时修法：把 `12 / 6.6 / 16` 改成读实际根字号（`parseFloat(getComputedStyle(document.documentElement).fontSize)`）× 0.75 / × 1，再按同比例算 gap。
- **验收**：`npx vitest run src/ui/accountOrder.test.ts`（现有用例都是 px 输入，需要补一条"根字号 18px 时 3 个长名字应降为 2 列"）；手工：1440 宽横屏 + 4 个中文长账号，账号格不溢出。
- **归属**：S2（`accountOrder.ts` 目前主要服务看板/家园/配窝卡）。
