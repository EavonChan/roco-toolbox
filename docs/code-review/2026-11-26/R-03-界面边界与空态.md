# R-03 · 界面边界与空态（我的 / 蛋仓 / 窄屏 / 横屏）

> 审查者：R4（只读）。**没有改 `src/`、没有 commit、没有 push、没有打包/发版、没有跑全量测试。**
> 行号基准：`d1a4f1c`（当前 HEAD）。引用前请先 `git show d1a4f1c:<file>` 复核。
> 分级：**P1** = 点了没反应 / 回错页面 / 看到错的事实；**P2** = 边界、发现性、空态、可确认项。
> 说明：本册的像素级结论（UI-07 / UI-08 / UI-09）**没有起浏览器实测**，是按 DOM 顺序 + 仓库内实现截图推的，已逐条标「推测」。UI-01 / UI-10 是代码路径实测（静态可判定）。

## 0. 结论

「我的」重构把三类入口拆成「概览卡 + 三个快捷入口 + 列表行」之后，**主链路（我的 → 蛋仓 → 返回我的）是通的**，`data-view-import` 之外没有 testid 被删到让现有测试变红（见 §12 对照表）。真正的问题是**动作按钮的落点**和**空态说实话**：

1. **UI-01（P1）**：已登录时概览卡上的按钮写「同步」，点下去只到「我的身份」页，而身份页恰恰把「立即同步」隐藏了 —— 用户点了个假动作。
2. **UI-12（P1）**：横屏家园在「这份数据里没有家园记录」时，整块 header 不渲染，而「刷新家园」按钮只挂在 header 上 —— 最需要刷新的状态下按钮消失。
3. **UI-10（P2，但与 P1 同级观感）**：换蛋广场的蛋仓在**加载中 / 接口失败**时也显示「暂无已采集的蛋」，用户第一眼看到的是假空态。
4. 其余是发现性（附近入口被压到页尾）、落点（快捷入口滚到 sticky 顶栏下面）、触区（26px）与两处「同屏两种口径」（上次采集时间、角色数）。

## 1. UI-01 · P1 · 已登录时点「同步」跳到没有同步按钮的页面

**位置**：`src/ui/ProfileHeader.tsx:69-76`（按钮文案 `loggedIn ? '同步' : '登录'`，回调统一走 `onGoAccount`）、`src/ui/Profile.tsx:201`（`onGoAccount={() => goSection('identity')}`）、`src/ui/AccountPanel.tsx:332`、`:343`（`section !== 'identity'` 才渲染 `account-sync` / `account-force-push`）

### ① 问题描述

- **现状**：「我的」首屏概览卡右上角的按钮，登录后文案变成「同步」，但点击只是把二级分区切到「身份」；而身份页里的 `AccountPanel` 明确用 `section !== 'identity'` 把「立即同步」「用本机覆盖云端」两个按钮**藏起来**了。
- **用户影响**：已登录用户在首屏看到「同步」，点下去只能看到用户名 / 改密码 / 退出登录，没有任何同步动作；他会以为同步已经开始（静默完成）或者功能坏了。真要同步得点「‹ 返回我的」→ 滚到页面底部「私有同步」。
- **触发条件**：**必然**，所有已登录用户第一次点这个按钮都会遇到。未登录时文案是「登录」，落点是对的。
- （技术证据：`ProfileHeader.tsx:75` 文案分支 + `Profile.tsx:201` 固定落 identity + `AccountPanel.tsx:332/343` 隐藏条件。`ProfileHeader.test.tsx:64-70` 只断言"回调被调用过"，不校验落到哪个页面，所以测试没拦住）

### ② 优化方案

三个改法，按代价排序，推荐 A：

- **A（最小改动，1 行文案 + 1 个落点）**：已登录时把文案改成「账号」，落点保持身份页 —— 诚实描述它去的地方。
- **B（保住"同步"这个动作）**：在数据页给同步卡加 ref，按钮改成滚动直达并高亮该卡（`AccountPanel` 的 `section="data"` 那一块）。代价：要处理 sticky 顶栏遮挡（见 UI-09）。
- **C**：新增 `ProfileSection = 'sync'` 二级页，把 `AccountPanel` 的同步区单独搬过去。代价：多一个二级页，超出本轮"少改界面"的边界。

选 A 的理由：这条算"文案与行为不一致"，A 把不一致消掉、零风险；B 需要一个新落点，建议和 UI-08 的入口重排一起做。

### ③ 优化后表现

- **解决**：用户不会在首屏看到一个点了不起作用的「同步」。
- **验收**：`npx vitest run src/ui/ProfileHeader.test.tsx src/ui/Profile.test.tsx`，新增用例「已登录时 `profile-header-action` 文案为『账号』（A）或点击后 `account-sync` 存在（B）」。

## 4. UI-04 · P2 · 蛋仓直达请求没被消费时会跨页残留，之后从别处进换蛋会被自动弹进蛋仓

**位置**：`src/ui/navigation.ts:110-157`（`tab` / `open-profile` / `open-collection` 只清 `eggStockFromProfile`，不清挂起请求）、`:177-179`、`src/App.tsx:276-286`（`openEggStock={eggStockPending(navigation)}`）、`src/ui/plan/EggMatchingHub.tsx:67-71`（`openStock` 一为 true 就开蛋仓并回报）

### ① 问题描述

- **现状**：从「我的」点「蛋仓」会发一个挂起请求（`eggStockRevision > consumedEggStockRevision`）。正常路径（已登录 + 有组）会被 `EggMatchingHub` 消费掉；但如果当时未登录 / 未入组（落到换蛋的登录/建组提示），或组详情还没加载完用户就切走，这个挂起请求会一直留着。等用户之后因别的原因进换蛋、且组已就绪，页面会**自动弹进蛋仓**；这时 `eggStockFromProfile` 已经被中间导航清掉，蛋仓里的「返回」指向换蛋，而不是「我的」。
- **用户影响**：用户被莫名送进蛋仓、按返回又回到一个他从没进过的页面。
- **触发条件**：**偶发**（需要请求未被消费），但只要"未登录点蛋仓"就会留下。
- （技术证据：`navigation.ts:110-157` 三个分支都只处理 `eggStockFromProfile`；`navigation.test.ts:149-160` 只断言来源标记被清，没有断言挂起请求被取消；`EggMatchingHub.stockBack.test.tsx` 用页面自己的按钮模拟，不走 `App.tsx` 的真实链路）

### ② 优化方案

① 未登录 / 未入组时不要让「我的」发 `open-egg-stock`（直接给 `EggStockView` 已有的 `egg-stock-need-account` / `egg-stock-need-group` 空态，或去登录页）；② 在 `tab`（离开 groups）/ `open-profile` / `open-collection` 时把 `consumedEggStockRevision` 推到当前 revision，显式取消挂起；③ 冷启动恢复时，`page==='groups' && eggStockFromProfile` 写回「我的」而不是换蛋。代价：三处各 1~3 行。

### ③ 优化后表现

- **解决**：点过一次蛋仓不会在以后某个时刻突然生效；返回目标始终等于来的地方。
- **验收**：`npx vitest run src/ui/navigation.test.ts`，新增「`open-egg-stock` 后 `tab dashboard` → `eggStockPending === false`」。

## 5. UI-05 · P2 · 同一屏上「角色数 / 上次采集」有两份实现、两种口径

**位置**：`src/ui/ProfileHeader.tsx:18-40`（自己 `reduce` 取 `importedAt`，格式 `month/day/hour/minute`，无年份）、`src/ui/ImportPanel.tsx:80-83`（同一字段再算一遍）、`:529-535`（渲染「N 个账号 · 上次导入 <完整日期时间>」）

### ① 问题描述

- **现状**：同一屏同时出现「1 个角色 · 上次采集 11/25 22:56」和「1 个账号 · 上次导入 2026/11/25 22:56:03」：一个有年份一个没有；一个叫"角色"一个叫"账号"；一个叫"采集"一个叫"导入"。而且 `ProfileHeader` 用的 `importedAt` 按 `src/domain/backup.ts:216-224` 的定义是**本机导入时刻**，不是抓包采集时刻。
- **用户影响**：用户会疑惑「角色」和「账号」是不是两个不同的数；更实质的是——今天导入一份上个月的旧抓包，概览卡会显示「上次采集 今天」，把这个页面「数据新不新」的唯一指标说反了。
- **触发条件**：**必然**；导入旧备份时影响最明显。
- （技术证据：`ProfileHeader.tsx:18-40` 与 `ImportPanel.tsx:80-83/529-535` 各自算一遍；仓库内实现截图 `U2-实现-375-改后-已导入.png` 同屏可见两种格式）

### ② 优化方案

把「上次导入时间」提到 `Profile` 层（或抽 `useLastImportedAt`）传给两个组件，统一一个格式化函数与用词。**需确认**：文案要保留「上次采集」就把取值改成 `exportedAt`（缺失回退 `importedAt`）；要保留 `importedAt` 就改叫「上次导入」。A（改取值，保留"采集"）= 语义更准但旧备份会显示更早时间；B（改文案）= 零风险。推荐 A，因为这一页的目的就是判断数据新旧。

### ③ 优化后表现

- **解决**：一屏只有一种时间口径，导入旧备份不会再被说成"今天采集"。
- **验收**：`npx vitest run src/ui/ProfileHeader.test.tsx src/ui/Profile.test.tsx`，新增「概览卡与导入卡时间文案一致」+「`exportedAt` 早于 `importedAt` 时显示 `exportedAt`」。

## 6. UI-06 · P2 · 概览卡没接加载态，冷启动先闪「还没采集过数据」；头像显示「已」

**位置**：`src/ui/ProfileHeader.tsx:30-41`（无 `loaded` 入参）、`:53`（`nameText.slice(0, 1)`）、`src/ui/Profile.tsx:101`（`useSnapshots` 有 `loaded`）、`:198-202`（只传 3 个 prop）

### ① 问题描述

- **现状**：冷启动时 `snapshots` 先是空数组，概览卡立刻显示「还没采集过数据 · 先在下面导入一次」，等 IndexedDB 读完才变成「N 个角色」。`accountName` 是可选项、生产调用方从不传，`nameText` 落到「已登录」，头像取首字就是「已」。
- **用户影响**：老用户每次冷启动先看到一句错误事实；已登录用户看到一个「已」字头像，而这张卡本来是要回答"谁在用"。
- **触发条件**：**必然**（冷启动）；「已」头像对**所有**已登录用户恒成立。
- （技术证据：`git grep -n 'accountName=' d1a4f1c -- src/ui` 只命中 `ProfileHeader.test.tsx:46`；实现截图 `U2-实现-蛋仓返回-2-回到我的.png` 里头像就是「已」。`ProfileHeader.test.tsx:41-54` 测的是生产不会走的分支）

给 `ProfileHeader` 加 `loaded?: boolean`：未加载时显示「正在读取本机数据…」而不是「还没采集」；`accountName` 通过账号摘要接进来（方案 §4.5 已提），拿不到时用中性的「我」或图标，不要用「已登录」首字。代价：两个可选 prop + 一处取值。

### ③ 优化后表现

- **解决**：冷启动不再闪假空态；头像能显示真实用户名首字。
- **验收**：`npx vitest run src/ui/ProfileHeader.test.tsx`，新增「`loaded=false` 不出现『还没采集』」「不传 `accountName` 不出现『已』」。

## 8. UI-08 · P2 · 「附近精灵」入口被压到整页最底部

## 10. UI-10 · P2 · 蛋仓在加载中 / 接口失败时也显示「暂无已采集的蛋」

### ① 问题描述

- **用户影响**：新入口直达的第一眼就是"你一颗蛋都没有"——用户会以为蛋仓空了或坏了。失败时"读不出来"和"确实没有"两种状态互相矛盾，用户不知道该重试还是去采集。

### ③ 优化后表现

- **解决**：加载中不再说"没有蛋"；失败时用户知道该重试。
- **验收**：`npx vitest run src/ui/plan/EggMatchingHub.test.tsx src/ui/plan/EggStockPanel.test.tsx`，新增「loading 时出现『正在读取』且不出现『暂无已采集的蛋』」。

## 12. UI-12 · P1 · 横屏家园遇到「这份数据里没有家园记录」时，页面上没有任何刷新按钮

- **用户影响**：这恰好是"刷新家园"最该出现的状态——用户导入了一份没进过家园的抓包，页面文案让他"进家园走一圈再刷新"，但横屏下按钮**不存在**；他只能转竖屏或重新导入。功能在一种屏幕方向下消失。
