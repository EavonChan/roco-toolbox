# 三维数据「时有时无」排查（2026-11-24）

> 只读排查，未改任何 `src/` 代码、未打包、未发版。
> 结论先行：**最可能的原因不是采集丢了，而是「三维」这个功能目前只在 `test`（内测）分支里，正式版线上还没有**；其次才是旧数据兼容与整份快照覆盖。

## 一、结论摘要

| 可能性 | 结论 | 依据 |
| --- | --- | --- |
| **1（最高）** | 正式版没有这个功能，内测版/测试站才有 → 用户在不同客户端之间切换，看起来「时有时无」 | `individualBonuses` 不在 `release`；线上正式 bundle 无该字段，测试站 bundle 有 |
| 2 | 旧备份/旧快照没有可用三维；新版只认 `individualBonuses` 或 `rawFields`，不认旧的 `individualStats` | 旧字段只有名字没有数值；`individualBonusesOfItem` 无 `individualStats` 分支 |
| 3 | 云同步按「整份快照」取较新，旧版本客户端上传的快照会整份覆盖本地 | `mergeSnapshots` → `mergeImportedSnapshot` 直接返回 `incoming` |
| 4 | 家园卡靠 `captureId` 后缀匹配住户；匹配不上时整张卡没有 pet（不只是三维空白） | `Home.tsx` 的 `petsByInstance` |
| 5 | 渲染层缺字段就留空，没有兜底推算 | `NestPlanCard`：`bonuses = pet.individualBonuses ?? []` |

## 二、字段与改名历史

### 当前字段

`individualBonuses?: IndividualBonus[]`，元素形如：

```ts
{ name: '物攻' | '生命' | '魔攻' | '物防' | '魔防' | '速度', value: number }
```

- 类型定义：`src/domain/types.ts:105`
- 解析：`src/domain/individualBonuses.ts`（从 `rawFields.bytes["14"]` 解 protobuf）
- 采集器导出：`src/pcap-decoder/tools/pcap-json-app/src/core.js` 的 `protocolIndividualBonuses`

### 改名提交

```
46bf7f9  2026-11-23 22:38:31 +0800  EavonChan
feat(卡): 配窝卡接入真实个体三维，individualStats 改名 individualBonuses
```

- 只存在于 `test`、`pr/15`、`pr/20`、`trial/*` 分支；**不在 `release`**：
  ```
  git merge-base --is-ancestor 46bf7f9 origin/release  → 1（否）
  git merge-base --is-ancestor 46bf7f9 origin/test     → 0（是）
  ```
- 改名前后数据形状：
  - 旧：`individualStats: string[]`，**只有名字数组**（`stats.push(INDIVIDUAL_STAT_NAMES[...])`），没有数值；
  - 新：`individualBonuses: { name, value }[]`，带数值。

### 线上版本对照（2026-11-24 实测）

```
正式站  /assets/index-CsU6PiGS.js  1,309,500 B  individualBonuses=False
测试站  /assets/index-Dhf8s1i0.js  1,336,645 B  individualBonuses=True
```

正式站 bundle 里连 `individualBonuses` 这个字段名都没有，说明**正式版压根没有三维渲染代码**。

## 三、完整链路（谁写、存哪、谁读）

```
PCAP
 └─ convertPcapBytes()  core.js
     └─ payload.collections.petBackpack.items[].individualBonuses   ← 采集器导出（含数值）
         └─ parseBackup()  src/domain/parseBackup.ts:264
             └─ AccountSnapshot.pets[].individualBonuses             ← 导入时清洗
                 ├─ IndexedDB `locke-toolbox` / snapshots            ← 本地快照（原样存）
                 └─ 云同步 buildSnapshot → gzip+base64 → PUT /api/sync
                     └─ mergeSnapshots()  src/domain/backup.ts       ← 按「整份快照 + 时间」取较新
                         └─ Home.tsx  petsByInstance()               ← captureId 后缀 = 住户 instanceId
                             └─ HomePairCards → NestPlanCard
                                 └─ pet.individualBonuses ?? []       ← 缺了就是空白
```

可能丢字段的位置：

1. **`parseBackup`**：item 没有 `individualBonuses` 且没有 `rawFields.bytes["14"]` → `undefined`；
2. **`mergeSnapshots`/`mergeImportedSnapshot`**：只要 incoming 更新的时间戳更晚，整份替换，没有字段级合并；
3. **`petsByInstance`**：`captureId` 缺失或后缀对不上 → 整张卡 `pet` 为空，三维、性格、声音一起空；
4. **渲染层**：`NestPlanCard` 直接 `?? []`，缺了不报错、不留痕。

## 四、证据：两份对照 pcap 都能解出三维

用仓库自带解析器跑了 `D:\download\capture-内测.pcap` 与 `capture-正式.pcap`（同号同场景）：

```
=== capture-内测.pcap
items 610 withIndividualBonuses 610 withRaw14 610 withIndividualStats 0
=== capture-正式.pcap
items 610 withIndividualBonuses 610 withRaw14 610 withIndividualStats 0
样例：机械方方 → 物攻+8 / 魔防+8 / 速度+10
```

结论：**采集阶段没有丢**。正式版空白只能是「客户端版本没有这段渲染」或「导入/合并后字段没了」，与 pcap 无关。

## 五、复现与验证步骤（用户可操作）

1. **版本对照（最快）**
   - 手机开正式版 → 家园卡片三维应始终空白；
   - 打开内测版/测试站（`test.roco-toolbox.pages.dev`）同一账号 → 有三维。
   - 若这条成立，根因就是「正式版没发」，不用再查数据。
2. **看本地快照里到底有没有字段**
   - 浏览器/WebView 开发者工具 → IndexedDB `locke-toolbox` → `snapshots`；
   - 看 `pets[].individualBonuses`：有 → 数据在，是渲染/版本问题；没有 → 是导入/合并问题。
3. **旧备份对照**
   - 导入 11-23 之前导出的备份 JSON → 预期空白（旧字段只有名字、无数值）；
   - 若该 JSON 带 `rawFields.bytes["14"]` → 新版会兜底解出。
4. **云同步复现**
   - 用旧版本客户端上传一次快照（较早时间）→ 在新版里「同步」；
   - 若云端那份 timestamps 更晚，`mergeSnapshots` 会整份取云端 → 三维消失；重新导入新抓包又出现。

## 六、修复建议（只列方案，不动手）

1. **先发版**：把 `test` 的三维功能转正到 `release` 并发正式站；这是当前「时有时无」的最大来源。
2. **补旧格式兼容**（可选）：`individualBonusesOfItem` 增加 `individualStats` 分支——但旧数据只有名字没有数值，无法显示 `+9`；建议只用于「知道有三维但数值缺失」的标记，不要伪造数值。
3. **合并策略**：云同步/导入时，若 incoming 的 pet 缺 `individualBonuses` 而本地有，建议字段级保留（或按 `catalogVersion` 拒绝旧客户端快照覆盖）。
4. **渲染兜底**：家园卡在缺三维时给「—」或 tooltip「该快照未采集个体三维」，避免用户以为是随机丢数据。
5. **匹配健壮性**：`petsByInstance` 失败时回退到「同名唯一」已有逻辑；可再加一条「按 actorId」兜底，减少整卡空白。
