# 文件存放规范

> 2026-11-22 制定。起因：根目录堆了 40 多个散文件，打开没有看的欲望。
> 一句话原则：**根目录只放「入口、配置、构建脚本」，其余一律进分类目录。**

## 一、根目录允许出现的文件

只有这几类，新增别的一律往目录里放：

| 类型 | 文件 |
| --- | --- |
| 入口 | `index.html`（Vite 入口，**不许移动**） |
| 说明 | `README.md`、`AGENTS.md`、`LICENSE` |
| 包与构建配置 | `package.json`、`package-lock.json`、`vite.config.ts`、`tsconfig*.json`、`tailwind.config.js`、`postcss.config.js`、`wrangler.toml`、`vitest.data-pipeline.config.ts`、`playwright*.ts` |
| 日常启动脚本 | `刷新数据.cmd`、`启动手机版.cmd`、`构建线上版.cmd` |
| git 配置 | `.gitignore` |

**不允许**：截图、原型 HTML、一次性文档、临时脚本、日志、压缩包、安装包、`.tsbuildinfo`。

## 二、目录职责

| 目录 | 放什么 | 不许放 |
| --- | --- | --- |
| `src/` | 产品代码（domain / ui / collector / api …） | 原型、截图 |
| `docs/` | 文档：规范、交接、方案、审查报告、领域模型 | 可执行原型（进 `原型/`） |
| `原型/` | **所有在用的可交互 HTML**，见 §三 | 产品代码、构建产物 |
| `docs/prototypes/` | **历史原型归档**（含 `shared/` 外壳）。文件之间有相对路径依赖，已冻结 | 新原型（新的一律进 `原型/`） |
| `docs/设计资产/` | 设计资产台账（`registry.json`）、采用稿索引 | 原型文件本身 |
| `docs/code-review/` | 审查报告与证据（按日期分目录） | 代码 |
| `data/` | 运行时数据（图鉴、性格表等 JSON） | 临时导出 |
| `public/` | 静态资源（图标、清单、`version.json`） | 原型 |
| `scripts/` | 可执行脚本（发版、预检、数据处理） | 一次性调试脚本（进 `待清理/`） |
| `tools/` | 数据管线与分析工具 | 产品代码 |
| `e2e/` | Playwright 用例 | 截图 |
| `functions/` | Cloudflare Functions | 前端代码 |
| `desktop/`、`android-shell/` | 桌面端与安卓壳 | 共用前端代码 |
| `release/` | 安装包产物（gitignore） | 源码 |
| `dist/` | 网页构建产物（gitignore，发版脚本读它） | 手写文件 |
| `补充数据/` | 个人游戏数据（gitignore，**不要提交**） | 任何公共资源 |
| `待清理/` | 历史产物集中区（gitignore，见 §五） | 任何还要用的东西 |

## 三、`原型/` 的内部结构

```
原型/
  编辑器/     还在用的可交互工具（布局编辑器、拖拽调整器）
  预览稿/     一次性方案稿、改版预览（历史参考用）
  截图/       原型配套截图（375 / 390）
```

命名：`<主题>-<用途>.html`，例如 `需求卡-4列-重排版方案.html`。
带日期的方案写 `预览-体重百分位-2026-11-16.html`（`-YYYY-MM-DD` 放最后）。

## 四、新增文件该放哪（决策树）

1. 是产品代码？→ `src/`（领域 `src/domain/`、界面 `src/ui/`）
2. 是要给人看的文档？→ `docs/`，按主题进子目录
3. 是可交互原型？→ `原型/编辑器/` 或 `原型/预览稿/`
4. 是原型截图？→ `原型/截图/`；是验收截图？→ `docs/screenshots/`
5. 是脚本？→ 会长期用进 `scripts/`；一次性的进 `待清理/`
6. 是构建产物？→ 加进 `.gitignore`，不要提交
7. 拿不准？→ 先问，别往根目录扔

## 五、`待清理/`

- 一切**已经不需要但还想留几天**的东西：历史原型目录、旧截图、旧 APK、临时脚本、日志、构建残留。
- 整个目录在 `.gitignore` 里，进 git 状态看不会有噪音。
- **只归档，不自动删除**。要真删，由用户确认后手动删。
- 每月清一次：确认没用过的直接删掉整个目录，再重建为空目录。

## 六、禁止事项

1. 不要往根目录新建文件（除 §一 白名单）。
2. 不要移动 `index.html`、`dist/`、`public/`、`release/` —— 构建与发版依赖这些路径。
3. 不要移动 `docs/prototypes/` 里的文件 —— 它们之间有 `../shared/` 相对依赖，移动会断样式。
4. 不要 `git add` 构建产物、截图、`补充数据/`。
5. 不要删除 `待清理/` 之外的东西来"整理" —— 先归类，再问。
