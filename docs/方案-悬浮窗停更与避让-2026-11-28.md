# 悬浮窗 OV1：停更自愈、停更不清空、窗口别盖住球（2026-11-28）

> 起因：用户反馈「悬浮窗体验不好」「球在边上的时候，悬浮窗容易盖住球」。
> 诊断依据：`tmp-diag/nearby375/` 与 DIAG1 回执（快照 TTL 3 分钟、H01 代次错位、心跳无回执）。
> 结论：①② 是实现（明确 bug）；③ 先出 A/B/C 三方案与截图，用户拍板 A 后已实现（2026-11-28）。

## ① 停更不再永久

### 成因 1：裁剪后两代字节被拼在一起（H01）

- 壳：战斗模式文件超过 8MiB 时，`PcapWriter.trimIfNeeded()` 把文件重写成「24B 头 + 最近 4MiB」。
- 网页：`src/collector/nativeCollector.ts` 只比长度（`cached.bytes.length <= snapshot.size`），
  裁剪后新文件涨回旧长度时守卫放行，把新一代片段拼到旧一代前缀后面。
- 结果：帧头错位，每轮解码失败 → 快照永不更新，只能重载页面。

修法（已落代码）：

| 侧 | 改动 |
| --- | --- |
| 壳 | `PcapWriter` 每次成功裁剪 `generation++`；`CaptureState.generation` 随采集开始归零；`CaptureVpnService` 每轮落盘后同步；`inspectCapture` 返回 `generation`，拦截器响应头带 `X-Capture-Generation`；grant 的旧长度按响应时的真实文件长度收口（`CaptureSnapshot.open(from, total)`） |
| 网页 | `CaptureSnapshot` 加可选 `generation`；缓存记录代次；代次不同 / 变短 → **整份重读**；增量响应的代次对不上 → 回退全量。旧壳没有该字段时按原行为（长度判断）兼容 |

证据：

```text
npx vitest run src/collector/nativeCollector.test.ts   → 16 passed
gradlew testDebugUnitTest --tests ...CaptureFilesTest   → BUILD SUCCESSFUL（含 generation 断言）
gradlew assembleDebug                                   → BUILD SUCCESSFUL
```

真机验证：采集超过 8MiB 后（约等于地图/列表一直在动），不再出现「球还在、数据不动、必须重进页面」；
WebView 里 `window.__rocoLiveTick` 每轮仍被唤醒即可。

### 成因 2：心跳没有回执，壳不知道 WebView 已冻结

- `MainActivity.liveTickTask` 调 `evaluateJavascript(..., null)`，WebView 被冻结时是空操作，壳完全不知情。
- 修法：带回调记录最近回执时间；页面不可见 + 采集中，连续 **9s** 无回执 → `webView.reload()`；
  两次自愈至少隔 **30s**，页面加载中（`pageReady=false`）不重复 reload，避免死循环。

真机验证：

```text
adb logcat -s RocoPerf
# 正常应看不到下面这行；被冻结并自愈时会出现：
# W/RocoPerf: WebView 心跳 9000ms 无回执，已 reload 页面自愈
```

## ② 停更时别清空

- 旧行为：`freshNearbySnapshot()` 超过 `NEARBY_SNAPSHOT_TTL_MS`（3 分钟）返回 `null`
  → payload `self=null / pets=[]` → `overlay-map.html` 的 `teardown()`，窗口看起来「变空了」。
- 新行为：悬浮窗改用 `retainedNearbySnapshot()`：
  - 换采集会话（session 不同）仍然失效，上一局的精灵不会留在屏幕上；
  - 同一会话超过 TTL **保留最后一帧**，payload 带 `paused: true`；
  - 壳端 `NearbyOverlayModel.paused`，脚注位显示浅灰小字 **「已暂停 · 采集未在刷新」**
    （不弹窗、不红字，面板高度按有脚注预留 20dp）；
  - 采集恢复后 `updatedAt` 变新，下一次推送自动回到正常状态，不需要用户操作。
- 附近页（App 内）仍走 `freshNearbySnapshot()`，不改动。

证据：

```text
npx vitest run src/collector/nearbyStore.test.ts src/nearby/overlayPayload.test.ts src/nearby/useNearbyOverlayPush.test.tsx
→ 8 + 41 + 7 passed
gradlew testDebugUnitTest --tests ...NearbyOverlayModelTest → BUILD SUCCESSFUL（21 tests）
```

## ③ 窗口别盖住悬浮球（方案 A，2026-11-28 已实现）

### 现状实测（dp；面板 214×182，球 52，边距 8）

| 球位置（375×812） | 现状面板 x | 结果 |
| --- | --- | --- |
| 贴左 x=0（左边缘） | 60 | 不压球，间隙 8 |
| x=255（偏右） | 153 | **压住整颗球（52dp）** |
| 贴右 x=323（右边缘） | 153 | **压住 44dp（84%）** |

根因有两条：

1. `NearbyPanelController.placePanel()` 只分「球吸附右边缘」和「其它」两种情况；后者一律把面板放在球的右侧，
   超出屏幕再整体夹回，夹回来就压在球上。
2. `BattleOverlayController.snapSideOf()` 用**球心**距屏幕边 8dp 判定吸附，但 `clampToScreen()` 让球至少完整留在屏内，
   球心离边最近也有 26dp（52/2），**这个吸附条件实际永远不成立**。
   于是「球吸附右边缘 → 向左展开」的分支在真机上从没走过，右侧非吸附位置也一律向右展开。

### 三个方案（375 / 390 都有截图）

| 方案 | 球贴左 | 球贴右 | 代价 |
| --- | --- | --- | --- |
| **A. 贴球展开 · 留 12dp（推荐）** | 面板 x=64 | 面板 x=97（390：112） | 面板始终挨着球；球在屏幕正中、两侧都放不下时退化为「贴屏边 + 上下错开」，复用已有的 `OverlayGeometry.oppositeOfBall` |
| B. 窗口居中 · 不跟球 | x=80（390：88） | x=80（390：88） | 左右都稳，但离球 ≥28dp，球动窗口不动容易觉得脱节；球在正中时仍会压球，必须再叠上下错开 |
| C. 球让位 | 不变 | 面板仍在 153，球上移 64dp | 点开瞬间球跳 64dp（面板更高时更多），且球位置会写回存档，容易「越用越偏」 |

推荐 **A**：改动最小（只需要把 `placePanel` 的默认落点从「永远向右」改成「按球在左/右半屏选内侧、留 12dp」，
放不下时交给已测试过的 `oppositeOfBall`），视觉上窗口贴着球，用户一眼能建立「这是从球展开的」关系；
B 的居中会让窗口和球失去关联，C 会移动用户刚点的目标。A 还能顺手修掉吸附阈值永远不成立的问题（改用几何判断，不依赖 `snappedSide`）。

### 实现（2026-11-28，方案 A 定稿后落地）

- `OverlayGeometry` 新增三个纯函数：
  - `besideBall(...)`：贴球一侧落点，与球留 `gap`；横向放不下返回 `null`；
  - `panelSpot(...)`：优先 `besideBall`，放不下退化为 `oppositeOfBall`（贴屏边 + 上下错开）；
  - `snapToEdge(...)`：按球的**可见边缘**判定吸边，返回 `{x, side}`。
- `NearbyPanelController`：`PANEL_GAP_DP = 12`，`placePanel()` 改走 `panelSpot`；用户拖过面板（`userPositioned`）后
  尊重用户位置，只夹回屏内；面板展开期间球移动 → `setOrbRect` 检测到变化立即重排跟随（同一侧时 x/y 跟着球）。
- `BattleOverlayController.snapSideOf()` 改用 `snapToEdge()`：球可见边缘距屏幕边 8dp 内才吸附，
  吸附 / 半透明分支不再形同虚设。
- `android-shell/app/build.gradle` 的壳不变量校验同步改成「贴球 12dp / `panelSpot` / `snapToEdge`」，
  防止以后被回退成「永远向右展开」。

落点（dp；面板 214×182、球 52、间隙 12、屏幕边距 12）：

| 状态 | 375×812 | 390×844 |
| --- | --- | --- |
| 球贴左 | 面板 x=64–278 | 面板 x=64–278 |
| 球贴右 | 面板 x=97–311 | 面板 x=112–326 |
| 球在正中 | 面板 x=12–226 · y=146（贴屏边 + 上下错开 12） | 同上 |

单测：`OverlayGeometryTest` 10 tests 全过，覆盖贴左 / 贴右 / 居中、任意位置矩形不重叠且留 12dp、
球同侧移动跟随、可见边缘吸附。
