# 采择记录

> 用途：朋友（EavonChan）的提交进主线之前，留下一条**你自己的决定记录**。
>
> 原则：**不合并他的分支，只摘取**。朋友的 PR 是提案，不是合并候选。
> 工具：`node scripts/review-pr.mjs <ref>` 先预检，再决定摘哪些文件/提交。
> 配套：`.github/PULL_REQUEST_TEMPLATE.md`（他提 PR 时填）、`docs/会话分工与巡检机制-2026-11-22.md` §4。

## 一、他为什么要走这条路

| 他照旧做的事 | 你这边额外做的事 |
| --- | --- |
| 在自己的 fork 上开发、开 PR、用 AI 写代码 | 不点 Merge；先跑预检，再按文件/提交摘取 |
| PR 里填模板（改了什么、验证、截图、越界声明） | 摘完在下面记一条，写明为什么采纳、采纳了哪些 |

**对朋友的 AI 没有额外要求**：它不需要学新工具、不需要读这份文档、不需要改工作流。唯一两条硬要求写进 PR 模板即可——**base 用 `test`**、**一个 PR 一个目的（≤8 文件 / ≤400 行）**。

## 二、一次采择的标准动作

```powershell
git fetch eavon --prune                                   # 1. 拉他的最新
node scripts/review-pr.mjs eavon/friend/20261119          # 2. 预检：改了什么、禁区、重复补丁
git log --oneline test..eavon/friend/20261119             # 3. 看提交列表
```

然后二选一：

- **按提交**：`git cherry-pick <sha>`（适合单一目的、干净的提交）
- **按文件**：`git checkout <sha> -- <path>`（适合只想要某个文件的一部分改动）

第三种情况：**对方已经把你的 `test` 合进他的分支**（`fd877a1` 就是这样，`dd63724` 吃进过 `test@0284744`），
这时逐条 cherry-pick 反而会一路冲突。做法是 `git merge --no-commit --no-ff <ref>`，
再把不要的路径 `git reset` + `git clean` 掉，只提交 `src`/`e2e`（2026-11-22 那次这么做的，见 §三）。

摘完必须：跑相关测试 → 在下面记一条 → 再 push。
