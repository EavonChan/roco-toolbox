## 0. 结论先行

### 0.1 用户卡在哪一步

**不是"没有入口"，是"入口不叫绑定、而且不在他会去看的地方"。**

具体是三件事叠在一起：

1. **站内根本没有"绑定"这个动作。** 全仓 `src/**/*.tsx` 里"绑定"只出现 3 处：
   `EggTasksPanel.tsx:73`「对方未绑定QQ」、`:77`「待绑定QQ」（都是换蛋巡查的状态标签），
   加 `Nearby.test.tsx:307` 一行测试注释。**没有一处是"绑定游戏账号"的入口或按钮。**【实测 grep】
   真正的动作叫 **「选号并发布」**——在「我的 · 小组」的组卡里，勾选游戏账号 → 点「发布我的资源」。
   它写进 `mother_group_accounts` 的语义是"我向本组共享这几个游戏账号"，用户读到的是"共享母本资源"，不是"绑定账号"。
2. **大多数人是被"顺手"绑上的，所以产品从没教过这一步。** 导入游戏数据时会**自动**把本机账号发布到已加入的小组（`ImportPanel` → `autoPublishGroups`）。所以只要"先入组、后导入"，用户什么都不用做就通了——**这一步从来没有出现在教程里**（`tour.ts` 的 groups 分段只有"入组 / 广场在哪 / 发起与成交"三步，没有"发布我的账号"）。【代码事实】
3. **掉队的那批人（先导入后入组 / 从没导入过）没有任何提示。** 入组成功后**不会**触发发布（`onJoin` 只调 `hook.joinGroup`，无后续发布动作）；机器人那边报错只说"没绑定"，不说"去哪绑"。两头都安静，用户就只能问人。

> 一句话：**机器要求的是「小组 ↔ 游戏 UID」，用户做的是「小布助手登录」。这是三套不同的身份，产品从没在一处把它们摆在一起讲过。**

### 0.2 三套身份（这是混乱的根源）

| 身份 | 在哪绑 | 存在哪 | 谁需要它 |
| --- | --- | --- | --- |
| **小布助手账号** | 我的 → 我的身份 | 云端 `users` | 跨设备同步、小组 |
| **QQ ↔ 游戏 UID** | 群里发 `rc绑定uid` | 机器人本地 `GsData.db` | 机器人查询、群里 @ 人 |
| **小组 ↔ 游戏 UID** ← **本次卡的就是它** | 我的 → 我的小组 → 我的资源 → 选号并发布 | D1 `mother_group_accounts` | 机器人家蛋写进蛋仓、换蛋提醒找人 |

用户只做了第 1 件；机器人 `ingest` 要的是第 3 件。【实测 + 代码事实】

## 2. 为什么用户找不到（四条，按贡献度排）

### 2.1 入口措辞里没有"绑定"两个字（最主要）

界面上的词是「我的资源」「选号」「发布」，用户脑子里的词是「绑定账号」。
他会在「我的」里找"绑定"，看到的三个格子是「采集数据 / 我的蛋仓 / 我的小组」，
进「我的小组」看到的第一行是「我的资源 · 尚未发布」——**推荐动作是"选号并发布"，
而用户想要的"绑定"其实就在这里面**，但没有任何一处告诉他这两件事是同一件。

- 源码：`CollectionGroups.tsx:589-677`（`PublicationCard`）、`MotherResourceEditor.tsx:141-199`（账号列表）
- 截图：`B6-我的小组-从未发布.png`

### 2.2 自动发布会"顺手"完成，导致这一步被产品遗忘

`ImportPanel` 导入成功后调 `autoPublishGroups()`（`ImportPanel.tsx:189-210` → `groupAutoPublish.ts:163-188`），
把本机账号自动发布到**已加入**的组。所以：

- **先入组 → 后导入**：自动通，用户无感；
- **先导入 → 后入组**：`onJoin` 只做入组（`CollectionGroups.tsx:218-224`），**不会补发布**，用户就停在了"未发布"；
- **从没导入过**：面板是空态"本机还没有导入任何账号"，更无从下手。

推论：**出现这个报错的人，几乎必然是"先导入后入组"或"从没导入过"这两类。** 【推断（由代码路径得出，未对真实用户取数）】
`B6` 截图就是"先导入后入组"的样子：账号明明在，但状态是「未发布」。

### 2.3 机器人侧只转述错误，不给出口

- 服务端：`eggBotBridge.ts:83` 只回一个字符串 `'这个 UID 还没绑定到小组成员'`，**没有错误码**；
- 机器人：`roco_homeinfo/egg.py:118-119`
  ```python
  note = f'，蛋仓未同步（{reply.error}）'
  ```
  原文照抄进群里。**机器人既不知道"去哪绑"，也没有能力给链接/指路**（它只知道 QQ↔UID，不知道站内小组）。
- 结果：用户在群里看到一句话，回到 App 里没有任何呼应的地方——因为在 App 里搜不到"绑定"。

### 2.4 蛋仓/教程也没有兜住

- `EggStockView.tsx` 的空态只讲"未登录 / 未入组"（`先登录`、`先加入一个小组`），**没有"已入组但还没发布账号"这一档**；
- `tour.ts` 的 groups 分段三步全在讲广场与成交，**没有"发布我的账号"这一步**。

## 3. 数据侧：`mother_group_accounts` 是谁写的、要什么前提

### 3.1 全仓只有一个写入点【实测 grep】

```
$ grep -rn "mother_group_accounts" --include=*.ts --include=*.sql .
```
写入相关只有一处：

| 位置 | 语句 | 说明 |
| --- | --- | --- |
| `functions/_lib/motherGroupsStore.ts:513-534` | `INSERT INTO mother_group_accounts …` | **唯一 INSERT**，在 `publishMemberResource()` 里 |
| `functions/_lib/motherGroupsStore.ts:497-502` | `DELETE FROM mother_group_accounts … AND EXISTS(… write_token …)` | 同函数内，先删后插（整份替换语义） |

其余 9 处全是读：`motherGroupsStore.ts:354/571/618`、`collectionGroupsStore.ts:427/1239/1829`、
`eggReminders.ts:18`、`eggBotBridge.ts:81`。**没有任何第二个接口/任务/迁移会写这张表。**

### 3.2 写入链路

```
（自动）导入游戏数据成功
   └─ ImportPanel.tsx:189 afterImport()
        └─ groupAutoPublish.ts:46 autoPublishGroups()
             └─ syncGroup() → publishCollectionResources()
（手动）我的 → 我的小组 → 我的资源 → 选号并发布 → 发布我的资源
   └─ CollectionGroups.tsx:665 按钮 → useCollectionGroups.publish()
        └─ PUT /api/collection-groups/:id/resources
             └─ collectionGroups.ts:285 handlePublish()
                  ├─ 限流：WRITE_LIMIT（按 accountId）
                  ├─ 小组存在？        → 404 GROUP_NOT_FOUND
                  ├─ 是成员？          → 403 NOT_MEMBER   ★ 要登录 + 是该组成员
                  └─ publishMotherResourceToGroup()  (collectionGroupsStore.ts:1059)
                       └─ publishMemberResource()      (motherGroupsStore.ts:446)  ★ 唯一写点
```

### 3.3 写入前提（缺一条就写不进去）

| 前提 | 谁校验 | 不满足时 |
| --- | --- | --- |
| 已登录（有 `accountId`） | 路由层 | 登录表单 / 401 |
| 是该小组成员 | `collectionGroups.ts:297` | 403 `不是该组成员` |
| 本机导入过该账号的快照 | `MotherResourceEditor` 的 `snapshots` | 面板空态「本机还没有导入任何账号」 |
| 该账号有游戏 UID（`gameId > 0`） | `parseBackup.ts:73-74` | 键变成 `name:<账号名>`，**永远不会等于 `uid:<n>` → 机器人永远认不出** |
| 该 UID 在本组没被别人占用 | `motherGroupsStore.ts:545-553` | 409 `游戏账号已由 X 共享` |
| 客户端的 `baseRevision` 没过期 | `motherGroupsStore.ts:539-541` | 409 `小组资源已被其他设备更新` |

> ⚠️ **第 4 条是个隐蔽的坑**：`accountKeyOf()` 在 `gameId <= 0` 时返回 `name:` 前缀，
> 而 `ingest` 查的是 `uid:<数字>`。万一某个用户导入的数据里 UID 解析成了 0，
> 他发布成功、状态显示"已发布"，但机器人**永远**报"没绑定"，且界面上看不出区别。【代码事实，未复现】

**不需要管理员/组长权限**——普通组员就能发布自己的账号。只有"生成 QQ 群接入码"是组主专属（`eggBotBridge.ts:29-30`）。

## 4. 三个改进方案（按成本从低到高）

### 方案 A：机器人引导（改文案 + 加错误码）——**推荐先做**

**做法**

1. 服务端把两处拒绝返回加上机器可读的 `code`（`functions/_lib/eggBotBridge.ts:79` / `:83`）：
   - `{ ok:false, code:'group-unbound', error:'这个群还没接入换蛋提醒' }`
   - `{ ok:false, code:'uid-unbound', error:'这个 UID 还没绑定到小组成员' }`
   机器人就不必靠字符串匹配中文。
2. 机器人按 `code` 选文案（`roco-abo` → `RocomUID/rocom_homeinfo/egg.py:118-119`），把"去哪绑"写进那一句：
   > `，蛋仓未同步：这个游戏号还没在小组里发布。请到 小布助手 → 我的 → 我的小组 → 我的资源 → 选号并发布，勾上 UID 293143 后点「发布我的资源」`
3. 多 UID 时避免刷屏：每条只写短句 `，蛋仓未同步：这个 UID 还没在小组发布`，
   整批回复末尾附**一次**完整路径。

**成本**：本仓库约 6 行（两处 `json()` 多一个字段 + 一条测试断言）；机器人约 10~15 行。
**风险：低。** 只增加字段、改文案，判定逻辑与状态码全不动；旧机器人忽略新字段仍然正常。
**风险点**：文案里写死界面路径，界面一改文案就过期——建议路径只写"我的 → 我的小组 → 我的资源"，不写按钮名。
**验收**：群发 `rc生蛋了吗`（用一个没发布过的 UID）→ 回复里能看到"去哪绑"；`rc生蛋了吗`（已发布的 UID）行为不变。

---

### 方案 B：站内引导（入组后提示 / 首次用机器人时提示）

**三种颗粒度，可单上也可叠**

| | 做法 | 改动量 | 风险 |
| --- | --- | --- | --- |
| B1 | **入组成功后自动补发布**：`onJoin` 成功后调一次 `autoPublishGroups()`（已有函数，导入路径在复用），并给一条"已把你的 N 个游戏账号发布到本组"的提示 | `CollectionGroups.tsx` ~20 行 + 复用 `groupAutoPublish.ts` | **中**。会把用户**全部本机账号**直接共享给全组，属于"替用户做决定"；隐私上要拍板（建议：只发"这次入组前已导入的账号"仍等于全发）。**必须先给截图确认** |
| B2 | **改文案**：`PublicationCard` 未发布时按钮从「选号并发布」改成「绑定游戏账号」或加副标题「（机器人认这个）」；`MotherResourceEditor` 标题「我的共享资源」下加一句"勾上的账号 = 机器人能认的游戏号" | 2~3 行 | **低**。但和现有"共享资源"语义并行，可能让老用户困惑，要一起看两处文案 |
| B3 | **蛋仓空态补一档**：`EggStockView` 加"已入组但还没发布账号"，并给「去发布」出口 | ~25 行 + 1 条测试 | **低**。属于空态补全，不是新界面 |
| B4 | **教程加一步**：`tour.ts` 的 groups 分段插一条"发布我的账号"，锚到组卡 | ~10 行 | **低**，但按约定"页面常驻文案只留事实，教学走 tour"，这条最合规 |

**成本**：B2+B3+B4 ≈ 半天；含 B1 ≈ 1 天（含截图确认轮）。
**风险总评：B1 中（隐私/越界），B2~B4 低。**
**验收**：新账号"先导入后入组"→ 进「我的小组」能一眼看到"还没发布/去发布"；蛋仓空态能说清是"没发布"而不是"没蛋"。

### 方案 C：QQ ↔ 游戏 UID 自动关联 —— **不建议现在做**

**做法**：用机器人侧已有的 QQ→UID（`rc绑定uid`）与站内 组→UID（`mother_group_accounts`）交叉，
`ingest` 时若 `uid:<uid>` 查不到，就按"发起命令的 QQ 号"去找该成员，自动补一条（或自动发布）。

**成本**：本仓库要新表/新列 + 组员↔QQ 映射 + 权限口径 + 迁移 ≈ 150~250 行 + 1 次迁移；
机器人侧 ~80 行（把 `ev.user_id` 传上来，现有 payload 只有 `botId/qqGroupId/uid`）。
**风险：高。**

1. **冒名绑定**：谁先在群里用某个 UID 发命令，就等于声明"这个号是我的"。
   而 UID 是**可枚举的**——现有 `rc生蛋了吗 <任意6位以上UID>` 就能查别人家园（见
   `docs/分析-机器人代码审计与改代码权限-2026-11-22.md` §P0-3）。
   合起来就是"一条命令就能把别人的号挂到自己名下，然后以他的名义进蛋仓/换蛋"。**这条足以否掉裸自动绑定。**
2. **跨组越界**：A 组的自动绑定会给 B 组的广场带来假库存。
3. **与现有语义冲突**：`mother_group_accounts` 现在是"成员**主动**发布的摘要"，带 `source_exported_at`
   与 CAS 版本号；自动插入会绕开"旧源校验 / 同源校验"，让摘要变成半自动半手动的混合物。

**如果一定要做**：只能做"**半自动 + 确认**"——机器人侧识别到未绑定的 UID 后，
私聊/群内回一条"要不要把这个号登记到小组？"，由**组主**（不是本人）确认，或要求本人先登录小布助手再点确认。
这已经不是"自动绑定"，成本回落到方案 B 量级，收益却不比 A+B 高。

### 7.1 结论先行

| 问题 | 结论 |
| --- | --- |
| 一个人能绑几个游戏号？ | **不限个，想绑几个绑几个**，都挂在**同一个小布助手账号（= 一个组成员）**下 |
| 要注册/登录几次？ | **一次。** 一个 QQ / 一个游戏 UID 都不需要单独注册 |
| 发布要操作两次吗？ | **不用。** 编辑器里可以一次勾多个游戏号，点一次「发布我的资源」全带上 |
| 现在会不会"按 UID 建成员"？ | **不会。** 全仓只有「建组 / 入组」这两件事会写 `mother_group_members`，发布只写 `mother_group_accounts`（§7.2 有 4 条 INSERT 的位置） |
| 那用户为什么会觉得要建两个账号？ | **措辞**：界面把游戏号叫「账号」，且**没有任何一句**说"一个人可以绑多个号、不用建第二个账号"；真建了第二个账号再发同一个 UID 只会撞 409「游戏账号已由 X 共享」 |
| 要改代码吗？ | **数据模型和接口一行都不用改**；只要改文案 + 一处聚合显示 + 补操作指引（详见 §7.4） |

### 7.2 数据模型：多 UID → 一个成员（【实测】+【代码事实】）

**表结构**（`functions/schema.sql:99-130`，增量迁移 `functions/migrations/2026-10-23-mother-groups.sql` 一致）：

| 表 | 主键 / 唯一 | 语义 |
| --- | --- | --- |
| `mother_group_members` | PK `(group_id, account_id)` | **一个人（小布助手账号）一行**；`account_id` 就是登录身份 |
| `mother_group_accounts` | PK `(group_id, game_account_key)` | **一个游戏 UID 一行**；`member_account_id` 指回成员 |
| 约束 | 同一 UID 全组只归一位成员；同一成员**可以**有任意多行 | 正是"一个人多个号"要的形状 |

**写入链路**（唯一写点，`functions/_lib/motherGroupsStore.ts:446-558`）：`publishMemberResource()` 先用 CAS 更新**成员行**的修订号，
再删掉本人在本组的旧账号行、按 `resource.accounts` 逐条 `INSERT`；每条 INSERT 的 `member_account_id` 都绑同一个 `accountId`
（`:513-534`）。**它不查也不写 `mother_group_members`**，所以发布多少号都不会多出成员。

**成员只在这两件事里产生**：**建组**（`collectionGroupsStore.ts:283`，组长自己入组）和**入组**（`collectionGroupsStore.ts:314`；
一期旧接口同形状，`motherGroupsStore.ts:179/197`）。四处都是
`INSERT INTO mother_group_members (group_id, account_id, display_name, joined_at)`——**只有 accountId，没有 UID**。
👉 全仓没有"按 UID 新建成员"的代码路径。

**实测**（内存 SQLite + 真实 `buildMotherResource()` + `publishMotherResourceToGroup()`，库用 `functions/schema.sql` 建）：

```
一次发布里打包了： uid:1001(主号) + uid:1002(小号)
发布结果： { ok: true, resourceRevision: 1, publishedAt: ... }

mother_group_accounts：
  uid:1001  ← member_account_id=a  (主号)
  uid:1002  ← member_account_id=a  (小号)

mother_group_members：
  a / 阿岚 / revision=1
  b / 小林 / revision=0          ← 没有因为多绑一个号多出成员

再绑第三个号后（同一账号第二次发布）： [{"member_account_id":"a","n":3}]   ← 仍是 1 个成员 / 3 个游戏号
第二个小布助手账号发布同一个 UID：被拒 → GAME_ACCOUNT_ALREADY_SHARED 游戏账号已由 阿岚 共享，不能重复占用
```

最后一行就是**用户如果真去建第二个账号会撞上的墙**：一个游戏 UID 全组只能归一位成员（`motherGroupsStore.ts:545-553`），
而提示只说"已由 X 共享"，用户不会想到"X 就是我自己，该用回原账号"。
