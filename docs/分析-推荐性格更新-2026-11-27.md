## 1. 键的语义：`natures` 的 key 到底是哪个 ID

### 结论【实测】

```
productEggNatures.natures 的 key
  = 图鉴 catalog.gen.json 里的 gameId        （wiki 的 game_id）
  = 备份里的 speciesPetId                    （账号数据里的物种 id）
  = floor(petConfId / 1000)                  （抓包里蛋配置 id 除以 1000）
  ≠ number（图鉴序号 / `精灵编号`）           （2 / 5 / 8 这种，同一编号可能是多个形态）
  ≠ key（pet_000001）                        （备份工具自己的 runtimePetId，对图鉴会错配）
```

### 证据链

| # | 位置 | 读到什么 |
| - | ---- | -------- |
| 1 | `src/data/catalog.ts:37-38` | 注释写死「key = 蛋的 gameId」；变量名 `productNaturesByGameId` |
| 2 | `src/data/catalog.ts:58-70` | 只有 `eggGameId === entry.gameId`（这颗物种自己就是一颗蛋）时才把列表写进 `eggRecommendedNatures`，所以 key 必须是「自成一蛋」的物种 `gameId` |
| 3 | `src/data/catalog.test.ts:34-52` | 单测遍历 `productEggNatures.natures`，用 `eggs.get(Number(key))` 回查 `gameId`，断言 `eggRecommendedNatures` 相等 |
| 4 | `src/pcap-decoder/tools/pcap-json-app/src/core.js:746` | `speciesPetId = petConfId > 0 ? Math.floor(petConfId / 1000) : null` |
| 5 | `src/pcap-decoder/miniprogram/utils/eggConfigIdentities.js` | 游戏自带蛋配置表：`"3001001":["喵喵",3001,…]`、`"3280001":["雪绒鸟_夏天的样子",3280,…]` → **`petConfId / 1000` 正好等于表里第二列的 `speciesPetId`** |
| 6 | `docs/domain/数据字段说明.md:36` | 备份字段表：`speciesPetId`「与 wiki 的 `game_id` 一一对应」 |

第 5 条是关键实测：解包出来的配置表自己就带着 `petConfId → (带形态的名字, speciesPetId)`，`floor(petConfId/1000)` 与 `speciesPetId` 在同一条记录里对得上，所以这个除法不是猜的。

## 2. 名称映射规则与匹配统计

攻略表的「精灵名称」是玩家口径写法的组合：`物种名（形态/颜色/别名）`，而图鉴是 `name` + `form` 两个字段。规则按优先级从硬到软：

| 规则 | 说明 | 命中 | 置信度 |
| --- | --- | --- | --- |
| A 名称完全一致 | xlsx 名称 == 图鉴 `name`，且是「自成一蛋」的条目；同名多条时用 `精灵编号` 收窄 | 165 | **实测** |
| B1 形态名完全一致 | 拆出括号内容，`name` == 主体名 且 `form` == 括号内容 | 2 | **实测** |
| B2 主体名即图鉴形态名 | 如「急急急鸭」其实是「鸭吉吉」的一个 `form`，括号里是玩家别称 | 4 | **实测** |
| B3 别名映射 | 9 条人工列出的语义映射（见 §3.3），每条都能说出理由 | 9 | **推断** |
| B4 形态名包含 | 括号内容（或其中 `/` 前那段）是图鉴形态名的子串，如「崖间」⊂「崖间地的样子」 | 24 | **实测** |
| B5 去后缀后相等 | 去掉「的样子 / 的形态」再比（本次 0 条命中） | 0 | **推断** |
| C 按图鉴编号唯一命中 | 名称对不上但该「精灵编号」在图鉴里只有一颗蛋（4 条错字/异体字，见 §3.2） | 4 | **推断** |

合计 **208 / 209** 行按规则落位，第 209 行（雪绒鸟 冬鸟）由 §3.1 的推断补上，最终 **209 / 209 全部落位**；落位结果一一对应 209 颗蛋（**无重复**）。209 行只对应 183 个精灵编号——有 14 个编号带多形态（鸭吉吉 6 个、丢丢 4 个…），一个形态一行、也是各自独立的一颗蛋。

几条容易踩的坑：

- **不能用「精灵编号」当主键**：209 行只对应 183 个编号，鸭吉吉一个编号（011）就有 6 个形态、6 颗蛋。
- **同名多形态时只认「自成一蛋」的那条**：例如「护主犬」在图鉴有 2 条（本来的样子 3070 / 看守麦田的样子 3870），后者 `eggGameId=3070` 不是独立蛋，所以唯一命中 3070。
- **括号里的内容经常只是玩家叫法**：`急急急鸭（领结鸭）` 里的「领结鸭」在图鉴里不存在，真正对的是「鸭吉吉 / 急急急鸭」。
