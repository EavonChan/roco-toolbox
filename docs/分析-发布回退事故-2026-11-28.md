## 恢复动作

```bash
# 1) release 独有的 3 个功能 cherry-pick 回 test
git cherry-pick 8c144c0 c06b984 cc37f0f      # 456a671 / c9cbd9e / c5b9c13
#    冲突：eggPatrolStock.ts(.test) —— 保留 test 侧的绿窝回填 + release 侧的变异分类

# 2) 全量验证
npm run verify   # 219 文件 / 2059 测试 + functions 11 + 文案 lint 全过

# 3) 从 test 重建，两站同发
node scripts/deploy-web.mjs --branch test --dist <build>
node scripts/deploy-web.mjs --branch main --approve-production --dist <build>

# 4) 把 test 并回 release（独立 worktree，避免动主工作区）
git merge origin/test   # 冲突取 test 侧（已含 release 改动且已验证）
git push origin HEAD:release   # origin/release = 7caa732
```

**结果**：两站 `index-Df3A_pko.js`（1,399,418 B），哈希一致；
关键功能标记全部命中（绑定游戏账号 / 没有找到你的游戏号 / 待认领 / 大块头 / 未知精灵 / 异色）。

## 根因

`release` 长期落后于 `test`（页面发布只更新站点、不更新 `release` 分支）。
只要有人从 `release` 构建发布，就会把 `test` 的全部改动回退。

## 规则（新增）

1. **发布前必须确认构建源**：`git rev-parse --short HEAD` 与要发的内容一致；跨分支发布前先比 `git rev-list --count origin/release..origin/test`。
2. **`release` 不允许长期落后**：每次正式发布后把 `test` 并回 `release`（或按 `docs/发版与更新规范.md` 转正流程走）。
3. **发布脚本应打印构建源**（建议后续在 `deploy-web.mjs` 里输出 `git rev-parse HEAD` 与相对分支的领先/落后数）。
