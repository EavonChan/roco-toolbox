# 命名规范（2026-11-22）

> 一句话规则：**用户看得到的地方用中文名，用户看不到的地方用 `roco-*` 标识。**
> 目的：不再出现"洛克工具箱 / 洛克王国工具箱 / 小布助手"三个名字混用。

## 一、名字怎么分层

| 层级 | 名字 | 用在哪 |
| --- | --- | --- |
| 品牌简称 | **小布** | 图标、slogan、极短文案（如"小布帮你算"） |
| 产品名 | **小布助手** | 网页标题、桌面/安卓应用名、商店/安装包、设置页、更新弹窗 |
| 机器人 | **小阿布** | QQ 昵称、群名片、机器人自称、提醒文案 |
| 技术标识 | `roco-toolbox` / `roco-abu` | 仓库名、域名、包名、存储键、环境变量、API 路径 |

**分工**：小布助手是"产品"，小阿布是"产品在 QQ 群里的分身"。两者可以同句出现：

- ✅ 小布助手已更新到 1.5.6，小阿布会在群里同步提醒。
- ✅ 在小布助手里点「催进度」，小阿布会 @ 对方。
- ❌ 工具箱更新了 / 机器人会提醒你 / 洛克工具箱。

**不要出现的第四个名字**：洛克工具箱、洛克王国工具箱、RocoToolbox、AbuBot、小布工具箱。
历史文档的**正文**保留旧名（那是当时的记录，改了反而失真），但**标题和索引**用新名，例如 `机器人能力全景-2026-11-17.md` 的标题已改为「小布助手 · 小阿布能力全景」；新写的文档一律用本规范。

## 二、技术标识：明确不改

| 标识 | 当前值 | 改了会怎样 |
| --- | --- | --- |
| 网页仓库 | `sasaki-ishiran/roco-toolbox` | GitHub 会 redirect 旧地址，但 clone 地址、CI、文档链接、朋友 fork 全要跟着动 |
| 线上域名 | `roco-toolbox.pages.dev` | **不能改**。origin 变了 = 浏览器本地身份/数据全部对不上，等于换一套数据 |
| 测试域名 | `test.roco-toolbox.pages.dev` | 同上 |
| Android 包名 | `com.localdatatool.toolbox` | 改了等于新应用，覆盖安装变共存，用户数据丢失 |
| 本地存储键 | `roco.*`（如 `roco.collectionRailCollapsed`） | 改了用户偏好/账号数据读不到，要做迁移 |
| 桥接 API 路径 | `/api/egg-bot/*` | 改了要机器人端同步发版，且旧机器人立刻失效 |
| 环境变量 | `ROCO_TOOLBOX_BRIDGE_TOKEN`、`EGG_BOT_BRIDGE_TOKEN` | 改了要重新配置两边，配错就是"静默不发" |
| 换蛋订阅名 | `[RocomUID] 工具箱换蛋提醒` | **不能改**。它存在 `subscribe.task_name` 里，改了旧群订阅全部失联 |
| 插件 SV 名 | `工具箱换蛋接入` 等 | 改了控制台配置项重建，群里的开关状态回默认 |
| 机器人仓库 | `roco-abu`（新建） | 新仓库，无历史包袱，可以自由命名 |

结论：**产品名已经改完，技术标识保持不动。** 这不是偷懒，是"品牌名"和"标识符"本来就该分开——标识符一改，数据、域名、安装包、历史订阅都会跟着断。

## 四、以后要改名，先过这三问

1. **用户看得到吗？** 看不到（变量名、日志、内部字段）→ 不改值，最多改注释。
2. **这个名字进过数据吗？** 进了数据库/本地存储/域名/包名/订阅表 → 必须走迁移，不能直接改。
3. **改了会不会让人以为换了个产品？** 会 → 要发公告 + 迁移指引，而不是悄悄改。

## 五、给未来的自己

- 新功能起名：先想"用户会怎么念"，再想"代码里怎么写"；两者不必相同。
- 新增文案里出现"工具箱"三个字时，先问一句：这是用户看的，还是给运维看的？
  - 用户看的 → 小布助手 / 小阿布
  - 运维看的（日志、报错栈、内部 task 名）→ 保持原样
- 机器人自称固定用「小阿布」，不要一会儿"我"一会儿"本机器人"。
